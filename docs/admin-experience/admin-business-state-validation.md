本批承接 PR #221，属于剩余清单第 8 项的分批交付。第 8 项整体仍未完成；不能将本批的 12 页查询检查计作 41 页全部业务验收通过。H5 真机综合验收按 2026-09-15 的用户要求暂缓。

## 已复现的问题与职责

- 注册审核使用独立的目标、选项及提交请求。共用 CRUD 的生命周期保护不能覆盖它，原测试也未覆盖审核期间换目标或重新登录。现由审核页面绑定目标和身份，旧选项不覆盖新表单，旧成功不关闭新表单；选项失败可重试，恢复前不能提交依赖租户与角色选项的通过决定。
- 系统工具、限流规则和敏感词的行启停绕过共用 CRUD，原测试只检查页面挂载，没有检查请求未结束时重复操作。三者复用 `useRowMutation` 的单行锁和身份边界，具体请求体、状态回滚和刷新留在业务页面。失败保留可恢复状态，只读系统工具仍展示启停状态。
- 角色页面将权限树失败转换为空数组，而保存时从树读取全量授权；后端 `RoleService.replacePermissions` 按契约覆盖已有关系，空数组会清空授权。之前角色夹具本身没有权限，无法暴露丢失。权限加载失败或进行中现在阻止保存；原地重试后恢复已选权限，身份变化废弃旧选项。
- 共用 `usePagedList` 已提供失败与旧数据状态，但多个页面仍同时显示空表，误导用户将请求失败理解为没有记录。本批统一渲染条件；操作日志与提示词版本页接入已有加载逻辑，提示词失败不再显示零值与空记录，比较选择随新结果或身份清除。
- 390px 下 Skill 与 SQL 定义的固定操作列遮住内容。先以实际点击命中位置复现，再让管理表格在窄屏整体横向滚动。桌面固定列保留；客服台和动态工作区不受这条样式影响。长昵称使用溢出提示，避免单行撑到约 1,095px。

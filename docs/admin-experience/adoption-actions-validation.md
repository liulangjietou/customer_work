# Badcase、词表批量操作与 SQL 子表验收（G22）

本批承接 PR #229，仍属于 P1 全站验收。三个页面的专项修复、后端相关回归和客服库 V30 迁移已验证通过；38 条相关浏览器及三张窄屏图已检查，最终完整门禁已通过；交付与远端 CI 状态以本分支关联 PR 为准。H5 真机按用户要求暂缓，P2 性能未实测。

## 调用链与职责

| 入口 | 下游 | 本批检查的边界 |
|---|---|---|
| Badcase 采纳与忽略 | BadcaseReview → BadcaseController → BadcaseGatewayProvider/Factory → BadcaseService → 客服库知识、评测与 Badcase 表 | 原身份与抽屉目标、重复采纳、写入失败后的原子性 |
| 敏感词选项与导入导出 | SensitiveWordManage → ContentGuard API → SensitiveWordService → 客服库词表 | 完整选项、导入输入保留、旧下载丢弃、精确租户唯一键 |
| SQL 参数、转换器和复制 | SqlDefineManage → SQL API → SqlDefineService → Admin 主子表 | 父子记录归属、旧响应、在途锁与复制事务 |

页面复用现有 `useQueryState` 和 `useRowMutation`；抽屉和子表表单各自保留目标代次。Badcase 的状态规则属于实体，多表写入属于服务事务；后台工厂直接创建服务，事务须显式绑定客服数据源。

## 原测试为何遗漏

- 原页面检查主要覆盖挂载、公共 CRUD 与列表查询，未扣留这些专用动作的响应来验证切换记录、确认期间重登和失败后重试。
- `BadcaseServiceTest` 使用内存 Store 和 KnowledgeMapper 替身，验证已有用例编号冲突与正常采纳，没有检查重复采纳后数据库中是否多出孤立记录，也没有执行真实多表失败回滚。
- `SensitiveWordServiceTest` 验证默认值、批量上限和导入格式，Mapper 替身无法覆盖数据库唯一键的排序规则及租户插件实际生成的 upsert。

## 失败证据

- 首轮 29 条浏览器均失败：27 条为实际状态或未处理异常问题；两条未找到关闭按钮。根据实际可访问性快照，将按钮名称改为“关闭此对话框”后，两条单独复跑，实际观察到 case-a 的旧采纳结果覆盖后来打开的 case-b。
- 真实数据库首轮 9 条中，SQL 父子修改/删除、复制与失败回滚三条通过，Badcase 正常双采纳/忽略/租户拒绝及词表正常往返两条通过。
- Badcase 三条失败分别证明重复知识采纳产生两条知识、重复评测采纳产生两条用例，以及 Badcase 状态写入失败后仍残留知识。
- 词表大小写租户测试首轮因原租户记录消失而抛出空结果异常。追加写入前状态与写入后全部记录诊断后复跑，确认导入将原 `ADOPTION-CASE / REVIEW` 改写成 `adoption-case / BLOCK`；不是空夹具或查询故障。
- 并发补查最初三条全部失败：同条记录双知识、双评测均重复成功，知识与评测并行丢失其中一个引用。加原记录行锁后这三条通过；随后不同 Badcase 争用同一评测编号仍真实失败，说明编号的“先查再 upsert”仍会覆盖别人的采纳结果。评测存储新增仅创建操作，内存用 putIfAbsent、JDBC 用 INSERT 唯一键原子拒绝冲突；原编辑与导入的 save/upsert 行为保持。
- 首轮新增窄屏检查在 Badcase 填写标题处实际失败。截图显示标签被设为整行宽度，但表单项仍横向排列，输入框被挤出抽屉；已在该页的窄屏样式中令标签与内容纵向排列。Night 导入及 Ocean 参数表单原轮通过，修复后的 38 条相关浏览器回归全部通过，三张窄屏截图已查看；完整浏览器再次覆盖这些路径。
- 每轮失败日志、退出码和报告分别归档，后续回归不覆盖原始失败证据。

## 已完成的前端验证

- 三个页面修复后，Admin 341 条单测、生产构建、29 条专项浏览器全部通过。
- 采纳、忽略和子表操作锁定原身份与记录；验证期间、请求期间锁定写入，失败保留输入，旧成功不关闭新表单。

## 后端修复与待验范围

Badcase 在当前事务内锁定原记录，再检查实体状态并创建回流目标；同一条记录的采纳与忽略由数据库行锁串行处理，服务事务保护目标记录和处理状态。后台直接装配的服务通过事务代理绑定客服数据源。相关回归 91 条全部通过，0 失败、0 错误、0 跳过；其中 13 条真实数据库验收验证了重复采纳无孤立目标、状态保存失败时回滚、精确租户词表往返与 SQL 父子操作及复制事务。其中四条并发用例在实际数据库锁等待后释放请求，验证同条记录的双知识、双评测、知识与评测并行，以及不同 Badcase 争用同一个评测编号。

新增客服库 V30，仅将 `cw_sensitive_word.tenant_id` 改为 `utf8mb4_bin`，保留词面原排序规则、历史词条及操作状态。V1/V22 等既有迁移不修改。V29 存量升级、镜像接管、迁移幂等、Admin 跨库装配与结构快照检查均已通过。两轮范围回归曾在完整镜像接管处失败：新增 V30 后，既需识别已包含该列定义的镜像，也需同步测试实际导入的手工初始化 SQL；最后只更新该列定义，保留原始断言及失败报告。生成的结构快照来自独立数据库实际导出。

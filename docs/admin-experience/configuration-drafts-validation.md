# 智能体模板与个人草稿工作流

本批接通 CONFIG-01 的模板、未完成配置保存、恢复与冲突保护。受控试用、候选评测和上线检查聚合继续实施，不能将模板建议当作已通过的验收。

## 调用链与职责

- 页面 `AgentManage.vue` 保留正式配置表单，`AgentScenarioTemplates` 提供售后、配送和 FAQ 三个场景，只填写可编辑内容，不绑定模型、工具或知识权限。
- `useAgentDraftWorkflow` 管理当前表单的未保存状态、写入确认与离开提醒；`AgentDraftDrawer` 读取个人草稿并恢复到编辑表单。浏览器不将配置正文写入 localStorage。
- `/api/aiconfig/agent-drafts` → `AgentDraftController` → `AgentDraftService` → `ai_agent_draft`。草稿按当前 Sa-Token 用户及租户隔离，不参与运行装配、动态菜单或渠道发布。
- 正式保存仍走 `AgentController` → `AgentService` → 原有关联校验、模型连通性、知识/Skill 冻结版本、缓存失效及渠道发布门禁。没有另设绕过门禁的应用入口。

## 保存与恢复契约

| 场景 | 行为 |
|---|---|
| 名称、编码或模型未完成 | 允许保存草稿，正式保存仍要求原有必填项 |
| 草稿写入 | 固定 UUID，`expectedVersion=0` 首次创建；后续比较当前版本后递增 |
| 多标签页同时修改 | 旧版本返回 `CONFIG_EDIT_CONFLICT`（30016），不覆盖新内容 |
| 草稿写入响应丢失 | 查询同一 ID，仅在配置内容和关联目标一致时确认保存；不能确认则保留输入 |
| 草稿读取 | 列表仅返回概要；详情、修改和删除均按归属人与租户过滤 |
| 删除 | 比较草稿版本，防止误删其他标签页新保存的修改 |
| 恢复新建草稿 | 填充表单，不调用模型；未选模型保持未验证 |
| 恢复已有智能体草稿 | 读取当前正式配置；修订不匹配时保留草稿并阻止覆盖 |
| 正式保存 | 编辑页面携带 `X-Agent-Revision`；服务在同一事务中原子比较并推进修订，然后执行原保存链路 |
| 正式保存失败 | 保留表单与草稿，并就地展示错误 |
| 正式保存成功 | 再按版本清理个人草稿；清理失败只提示核对，不把已成功的正式保存再执行一次 |
| 未保存时返回或切路由 | 可以继续编辑，或明确放弃未保存修改；页面刷新/关闭使用浏览器原生提醒 |

草稿 JSON 使用固定配置 DTO，单份最多 64 KB，名称最多 200 个 UTF-16 单元。嵌套正式配置的必填校验不在保存草稿时执行；应用时仍受正式入口及服务校验。已有接口不带 `X-Agent-Revision` 时保持兼容，新页面使用后端返回的 `runtimeRevision`。保存草稿所需权限为 `agent:view` 加对应的 `agent:add` 或 `agent:edit`；本人草稿读取/删除还要求至少一项配置写权限。

## 本批确认并修复的交互问题

1. 模型 A 的迟到成功响应会覆盖已失败的模型 B；关闭后重开同一模型时也会受旧请求影响。为模型与表单生命周期增加请求序号，旧结果立即失效。
2. 资源选项原先一次 `Promise.all` 读取所有配置接口；缺少 MCP 等资源权限时，拒绝响应会连带丢弃已经有权查看的模型选项。现在按对应资源查看权限独立读取，读取失败可重试，并保留当前配置。没有模型测试权限时不发测试请求，仍可先保存草稿。
3. 新建草稿恢复时，两个空模型值不能被当成“原模型未变且已验证”。已增加明确的已有智能体条件，并用刷新后的实际按钮状态验证。
4. 正式保存请求失败原先会产生未处理的 Promise 异常。本页现在接住失败并保留输入，原请求错误信息在页面可见。

旧测试以保存成功和完整权限夹具为主，没有包含延迟请求、无权接口拒绝与恢复空模型；本批针对这些边界增加浏览器回归。网络断开用例只允许它主动制造的一条 `net::ERR_FAILED`，其余控制台错误仍视为失败。

# 管理页动作与身份生命周期验证

2026-09-15，第 8 项全站业务验收中发现的共用问题。完整工作包仍未完成。

## 调用链与根因

用户/角色/模型/Skill/系统工具/知识库/敏感词/限流/SQL 数据源/SQL 定义/工作台站点，以及只读 AI 审计页面 → useCrudPage/usePagedList → 各页 API → request.ts → 后端权限校验。

- 原用例覆盖普通成功、失败重试、重复点击与查询先后顺序，没有在确认、校验或保存等待期间切换页面、登录或编辑目标。
- 旧删除确认结束后才创建请求，会带上此刻的新身份。网络拦截器无法替尚未发送的确认动作还原发起身份。
- 旧表单校验结束后读取后来编辑的 id/form；旧保存结果还会关闭新弹窗、清除新动作的 loading。
- 共用列表会保留上个登录的结果，成功返回的数据也需由页面检查归属。
- permission 指令只在挂载时检查一次并删除节点，无法响应当前权限撤销与恢复。
- 用户管理的昵称同步是 update 回调内部副作用，共用 CRUD 在回调返回后才校验身份，无法替代该回调自己的校验。
- 原单元测试把提交拒绝当作预期结果，真实模板事件没有调用方接住，接口失败变成了页面未处理异常。

## 修复职责

复用 useAuthSubmissionScope 的页面与登录代次校验。动作归属、弹窗代次及列表结果属于前端共用状态管理；接口参数和实际授权继续由后端裁决。

- 确认与校验完成后、请求发起前，以及结果返回后检查动作是否仍有效。
- 同令牌重登、改密门禁或权限变化，清除旧列表和表单上下文。
- 重开编辑目标释放旧 UI 状态；旧请求的 finally 不能释放后来动作的 loading。
- 当前动作保存/删除失败维持接口拦截器的错误反馈，消费写入拒绝、保留表单并允许原地重试。已发出的请求无法由 UI 撤回，不把忽略迟到结果解释为撤销后端写入。
- 指令观察当前权限，以独立属性及样式隐藏入口，保留 Vue 节点生命周期；与原 class/style/v-show 共存，卸载时停止观察。
- 用户昵称同步再次检查发起身份；注册审核、系统工具开关等专属动作不自动落入共用 CRUD 的验收范围。

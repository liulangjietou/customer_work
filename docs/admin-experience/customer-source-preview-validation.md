# 客户消息原文与当前授权

基线：客户答复留存 PR #209，`c7658072`。本批接通客户消息内参考资料目录和历史段落，同时修复后台权限变更后客服投影仍可读取的问题。

## 调用链与职责

- H5 当前或历史 BOT 消息 → `UserMessageSourceController` → `UserMessageSourceService` → `UserMessageSourceDao` → `KnowledgeChunkMapper.findPublicSource`。
- HTTP 入口从 JWT 恢复租户上下文后执行阻塞存储读取；DAO 同次 JOIN 客服消息与工单，显式绑定 JWT 租户和用户，复验精确消息号、会话号、BOT 类型和工单关联；租户大小写沿用项目 `sameTenant` 语义。客户端只传消息内的来源索引。
- 来源来自已落库 `ChatAnswerEvidence.retrievalSources` 的完整内部引用；重复引用在目录去重，但索引保留原持久列表位置。模型文字和工具局部序号不能成为文档标识。没有记录的旧消息返回空列表。
- SQL 在同一次查询内校验租户、知识库、版本、修订和分片，并要求版本 `READY` 与分片 `PUBLIC`。目录不读取正文；预览只取历史片段与历史标题，知识库版本号和上游版本均来自真实投影。

默认 `customer-work.tenant.enabled=false` 时，租户 SQL 插件未安装。本批查询不能依赖该可选插件：受管检索的版本目录、公开分区、向量、正文和客户原文均显式限制发起租户。原生工具从 `AgentInvocationIdentity` 恢复本轮租户，`ManagedKnowledge` 在异步调度前冻结并在阻塞回调内恢复；缺少租户不查询数据或调用 embedding，也不回落到 default。配置开关保持原行为。

## 客户接口

`GET /api/customer/user/sessions/{sessionId}/messages/{messageId}/sources` 返回平铺数组；增加 `/{sourceIndex}` 返回一个平铺预览对象。

字段：`sourceIndex`、`status`（`AVAILABLE` / `UNAVAILABLE`）、`title`、`knowledgeBase`、`versionNo`、`sourceVersion`。预览另有纯文本 `content`，不返回内部资源标识、查询、分数、轨迹或完整文档。

| 情况 | 行为 |
|---|---|
| 当前有权且历史段落存在 | 200，当前授权下的历史资料 |
| 已撤权、删除、未重新投影、旧引用不完整 | 200 `UNAVAILABLE`，全部资料元数据和正文为 null |
| 旧消息没有留存来源 | 目录 200 空数组，访问不存在的索引为 404 |
| 会话/消息不存在、非本人、消息关联不符、越界索引 | 404 |
| 存储故障或未装配知识存储 | 503，可重试，不冒充空列表或资料失效 |

业务响应使用 `Cache-Control: no-store`。每次打开、返回列表和重新核验都重读；授权事实以当次 SQL 读取为准。已打开的资料不由后台权限变更主动推送清除，重新请求时会核验。

## 后台撤权与投影

后台 KB/source 编辑、启停、删除、同名 KB 复活与同步提交，统一先获得 KB 行锁，再按需获得 source 行锁。入口先验证请求，随后通过独立客服数据源同步提交该 KB 所有版本 `BLOCKED`，成功后才写后台权限事实。

客服库封锁失败则后台事务失败；后台后续回滚仍保留客服封锁。重新投影在同一个 KB 事务锁内读取完整成员及当前权限，执行目标版本 `BLOCKED` → 稳定主键 upsert → 删除多余片段 → 目标版本 `READY`。其他旧版本保持封锁，须逐一显式重新投影；不在后台事务提交后异步恢复授权。

有效公开权限为：历史修订 `PUBLIC` ∩ 当前修订 `PUBLIC` ∩ 当前文档未删除 ∩ KB/source 已启用且未删除 ∩ 正确的租户/KB/成员/文档/修订/来源关系。源默认 ACL 是未来同步的模板，不改写既有修订。同步提交同时比较 checkpoint 和源 `revision`，拒绝在事务外准备期间已变化的默认 ACL。

- 客服端新增 **V28**，Admin 仍为 **V106**，没有新表。新增版本授权状态/版本号、片段历史标题/上游版本四列。

# 运营看板查询与精确租户过滤验收

本批承接 PR #223，继续 P1 第 8 项逐页业务验收。第 9 项性能尚未测量；H5 真机综合验收按用户要求暂缓，未登记为通过。

## 根因与职责

| 调用链 | 原问题与职责 | 本批改动 |
|---|---|---|
| CSAT / 死信 / SLO / 业务结果看板 → 多个查询接口 | 手工 Promise.all 缺少错误恢复及发起身份检查，旧成功可恢复旧账号记录 | 新增有多个实际调用方的 useQueryState，整份快照成功后更新；错误保留已有结果，权限或登录变化清空旧数据 |
| 语义缓存看板 → 分区目录 → 条目列表 | 分区失败与条目失败没有明确状态，错误时可能显示零指标 | 分区和条目独立读状态，分区读取成功后才继续；重试、真空列表与首次故障各自显示 |
| 账单 → 当前视图 → 账单/对账/成本/单价/配额 | 手写查询缺少身份隔离，Date.toISOString 把本地月初与凌晨日期偏移到前一天 | 对应查询有独立恢复入口；账单展示绑定已接受结果的总览/明细类型；默认日期使用本地日历字段 |
| Admin CsatBoardController → OpsAdminService → OpsGateway → MybatisCsatStore | 默认 scopeId 固定为 default，非默认租户查不到自己按租户写入的评价 | 未指定分区时由服务解析当前可信租户，汇总与明细共用同一解析入口 |
| CSAT 窗口与缓存运营列表 → MyBatis Mapper | 数据库故障被转换成空列表，前端无法识别读取失败 | 运营读取故障保留异常；缓存在线候选读取等容错逻辑保持原有职责 |
| Admin / starter 生产 SqlSessionFactory → TenantInterceptors | 租户等值条件跟随文本列排序规则，将大小写变体身份同时纳入读取、更新、删除与连接 | 精确租户拦截器只把条件右侧常量转为 BINARY，保持别名和 INSERT 原始租户文本；忽略表和缺上下文规则仍由既有实现负责 |

租户比较是公共隔离层的问题，修复放在统一拦截器扩展点。没有重构存量领域模型或逐页增添不同口径的租户判断，也没有修改迁移、忽略表清单、主题预设或 H5 产品代码。

## 先失败的证据

- 13 条浏览器用例全部先失败：六页缺少查询故障恢复组件并产生未处理异步错误，六页同令牌重登后仍显示旧记录；账单本地 2026-09-15 凌晨的月初被计算为 2026-08-31。
- Store 错误用例 4 条：3 条故障原先没有抛出，真实空结果对照通过。
- CSAT 真实库初次 HTTP 用例没有指定 Accept JSON，修正内容协商夹具后重跑，真实失败为默认分区回收数 0 而非 1、大小写租户混读 2 条而非 1；真实空窗口对照通过。
- 公共租户比较在独立 MySQL 库以 utf8mb4_unicode_ci 重现：SELECT、UPDATE、DELETE、双别名连接 4 条先失败；INSERT 文本和缺上下文 2 条对照通过。
- 补强“首次查询失败不显示零指标”后，缓存页面仍显示零统计的断言先失败，已补上对应状态条件。长文本列使用明确最小宽度和已有 tooltip，主题色不变。

## 边界

浏览器夹具验证实际 Vue、请求和交互；SQL 测试使用自有随机库，迁移与租户插件按各自测试范围装配。CSAT 的 MockMvc 使用真实 Controller/Service/运营库，但不包含 Sa-Token 过滤链，不能当成权限过滤链验收。公共租户测试使用最小真实 MySQL 表核对数据库比较语义，不能替代全模块回归。

本批没有关闭死信重开、缓存清空/删除、SLO 策略保存/评估/确认/历史、账单配额/单价/归集等专用写操作的全部生命周期。第 8 项继续维护最终逐页矩阵，不以六页查询通过冒充 41 页整体验收完成。

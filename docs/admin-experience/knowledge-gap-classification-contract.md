# 未命中来源与分类复核契约

基线：`7557c620`（PR #202）。本批继续接通 OPS-01 的来源、人工分类、优先级与复核记录；不将知识候选或整个 OPS-01 标记完成。

## 调用与归属

| 调用方 | 下游 | 业务影响 |
|---|---|---|
| KnowledgeBaseTools、KnowledgeInjectionMiddleware | KnowledgeGapRecorder.captureMiss → KnowledgeGapService → KnowledgeGapStore | 记录最近检索样本及计数，异步执行仍使用冻结的租户 |
| KnowledgeGapBoard | KnowledgeGapController → OpsAdminService → KnowledgeGapStore | 先分类筛选再排序取前 50 条，不让问候占满工作清单 |
| KnowledgeGapReviewDrawer | KnowledgeGapReviewController → KnowledgeGapReviewService → OpsGatewayProvider → MybatisKnowledgeGapReviewStore | 当前分类、理由、优先级与不可变复核记录 |

源数据与人工复核均落在客服端库，因此分类 CAS 更新和复核流水使用同一个本地事务。Admin 服务负责鉴权入口编排、参数校验与错误翻译；不依赖跨库事务，也不复制既有 ImprovementCase 的认领、SLA、评测或发布状态机。

## 来源事实

- 工具路径使用框架原生 RuntimeContext 参数注入，工具 Schema 仍只有 query。最近智能体与入口来自 AgentInvocationIdentity；自动注入路径的智能体以服务端构建期实际实例为准。
- KnowledgeGapRecorder 在调度前捕获来源和租户，写入动作进入对应租户并在结束后恢复原线程上下文。两参数旧调用保留兼容，Admin 记录器转发完整来源。
- 最近样本保存检索路径、智能体编码、渠道、会话类型及正常空召回结果。迟到的旧时间样本不覆盖更新的来源；下一次样本无来源时明确显示未记录，不继续冒用此前样本。
- 累计次数仍按原问题哈希与租户分区聚合，不代表独立客户数，也不能归到最近样本的单一入口。
- 不增加分类模型请求。当前检索链路没有可靠的统一意图结果，页面明确说明未采集；既有检索异常仍不计入正常未命中次数，人工可结合其他业务证据归为工具/依赖异常。异常事件与已有意图的进一步关联仍待接通。
- 问题文本沿用原有 500 字符存储上限；历史记录没有消息关联及完整长问题，不把看板文本称为完整会话原文。

## 分类与并发契约

- 分类包括待分类、知识不足、工具/依赖异常、流程问题、实时查询、闲聊/非业务。
- 只有完整且明确的问候、日期/时钟问题产生规则建议；包含业务内容或语义不明的提问仍待分类。新增信号使用截断前的提问判断，历史已达 500 字符的记录不自动分类。规则建议标记为 RULE，不冒充人工结论。
- 默认工作清单排除实时查询、闲聊/非业务，但人工高优先级仍保留。原始记录没有删除，全部信号和各分类均可筛选。筛选发生在数据库 LIMIT 之前。
- 人工复核必须填写理由，操作人从当前登录态确定，正文不提供租户、分区或操作人字段。读取要求 knowledge-gap:view；写入同时要求 knowledge-gap:view 与 improvement:manage。
- expectedRevision 比较的是人工复核修订，正常计数增长不会造成编辑冲突。同一修订并发提交只有一个成功；分类和审计任一写入失败，两者一起回滚。新检索计数不覆盖人工分类和优先级。
- 复核记录保存前后类别、前后优先级、理由、操作人、时间及保存时的计数快照。每页 20 条，可继续读取更早记录。
- 页面保存失败或结果不明时保留输入并阻止再次写入，先读回当前服务器记录核对。冲突后的输入不会被读取结果覆盖；再次保存必须由使用者明确点击。
- 分类保存不会创建知识、运行评测或推进发布。补知识候选流程继续接通现有 ImprovementCase；旧 FAQ 直接写入接口保持兼容。

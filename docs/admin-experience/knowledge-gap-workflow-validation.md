# 知识缺口读取与治理交互验证

基线：`4354cbfb`（PR #201）。本批修正 OPS-01 的读取事实、治理操作对象与失败恢复；分类留痕、来源入口信号、知识草稿候选仍继续实施。

## 调用与职责

| 调用方 | 下游 | 影响场景 |
|---|---|---|
| KnowledgeGapBoard → KnowledgeGapController | OpsAdminService → OpsGatewayProvider → starter MybatisKnowledgeGapStore | 当前租户排行、查询失败、旧结果及重试 |
| 检索工具与注入中间件 | KnowledgeGapService → KnowledgeGapStore.recordMiss | 原有旁路未命中计数，写入失败不打断回答 |
| KnowledgeGapBoard、BadcaseReview | ImprovementClosurePanel → 既有 ImprovementCaseController / Service | 认领、目标用例、冻结候选、复评、可靠发布与状态同步 |

读写失败语义在 Store 分开：记录未命中是旁路统计；排行和原始信号查询属于运营事实，必须传播失败。租户分区由 OpsScopeResolver 统一解析，HTTP 参数缺省不再覆盖为固定的 default。显式分区参数保留兼容，实际 SQL 继续叠加当前租户过滤。

来源与请求状态在共享治理组件处理，因为知识缺口和 Badcase 使用同一套流程。后端候选、复评、发布与观察状态机保持其原有职责，本批没有另外引入状态机或发布接口。

## 失败复现

- Store 既有门禁只约束写侧；旧 topGaps / findAll 把 mapper 读取异常吞成空集合。新增两个最小失败用例分别覆盖，写侧容错另保留断言。
- 原有服务测试显式传 tenantA，没有验证缺省查询。新增服务用例在当前租户写入后用空分区查询，旧实现返回空榜。
- HTTP 用例以实际 Controller 和 OpsAdminService 验证参数绑定。最初 standalone MockMvc 未请求 JSON，误选 XML 转换器，不作为产品失败依据；补上 Accept 与响应类型断言后，重新对基线 Controller / Service 执行，确认 JSON 数据列表为空，恢复修复源码后再验证。
- 浏览器先稳定复现：初次读取失败没有错误/重试态；治理读取失败被当作尚未认领；切换问题后旧响应覆盖当前来源。
- 增补候选输入测试：修改智能体编号但未冻结时，旧实现仍允许发布原候选。修复后复评和发布均要求当前表单与已冻结绑定一致，重新冻结后必须重新复评。
- 抽屉原来固定 760 / 640px，超出 390px 视口；改为受视口约束。尺寸断言等待过渡动画结束，避免把动画中间帧当成最终布局。

## 行为契约

- 看板自动读取当前租户，频次只代表检索未命中次数，不当作独立客户数或真实知识不足结论。统计标明当前前 50 条，不当作全库总量。
- 初次失败指标显示“—”；刷新失败保留已加载结果并标记过期。此时停止基于旧列表开启写操作，重试成功后恢复。
- 治理初次读取尚未成功时不能认领；读取失败不能显示“未认领”。旧来源、已关闭抽屉和旧登录周期的响应不得覆盖当前内容或弹出成功提示。
- 治理写入结果不明时保留输入，先读取服务器记录核对；不会自动重发认领、复评或发布。读取仍失败时继续阻止写操作。
- 提交期间禁止并行操作。表单未保存的候选变化阻止复评及发布；提交对应源 ID 与候选参数由浏览器回归逐项核对。
- 无 improvement:manage 的组件不读取治理接口，避免仅隐藏 DOM 仍发请求。复评、发布继续分别要求 eval:run、agent:edit；只读 Badcase 抽屉也覆盖这一边界。
- 原始检索问题在抽屉顶部完整显示；责任、截止和状态优先展示，候选/评测/发布记录可展开。共享治理组件和两个抽屉完成窄屏尺寸检查。
- 旧 FAQ 补充 API 仍是直接写入线上 FAQ。页面明确标注其行为，保留失败输入，成功只说明条目已写入、效果待验证；不再承诺下次一定命中，也不把它标作草稿或自动闭环完成。

## 验证范围

真实 MySQL 测试使用随机临时库，经实际 OpsGatewayProvider、Flyway 与 AdminCrossDbTenantPlugins 装配，验证当前分区、相同分区下跨租户隔离、显式其他分区无法越权、缺失租户拒绝，以及数据库连接可用但表不可读时错误传播。只删除该测试创建的临时库。

前端回归使用实际 Vue 组件和隔离 API 夹具，覆盖故障、迟到响应、写入核对、只读、未过评测禁止发布、人工确认后创建发布任务、未冻结候选阻断，以及桌面/390px 几何与截图。它们不等同于真实模型或线上渠道发布联调。既有 ImprovementCaseService 测试另验证候选漂移拒绝、目标用例、渠道 APPLIED 与线上曝光观察门禁。

完整门禁通过：Maven 全模块 4001 项，0 失败、0 错误、7 项环境条件跳过；Admin 247 项单测和 162 项 E2E；H5 53 项单测和 6 项 E2E；两端类型与构建通过。7 项跳过为真实 RAG、百炼、4 项 Nacos 和 PaddleOCR；本次未将它们记为已执行。Redis 会话持久化、MySQL 网关与结构快照测试实际执行。

完整回归期间 16 个本批源码及测试文件保持冻结，并在结束后逐项校验 SHA-256。云凭据扫描、Compose 配置与差异检查通过。本批没有数据库迁移，结构快照仍为 Admin 90 张表、客服端 49 张表。

桌面与 390px 截图已在完整浏览器回归中重新生成并逐张检查，截图等待临时提示消失后采集。实际组件验收图见本地 `knowledge-gap-review.html`，演示夹具不代表生产发布。

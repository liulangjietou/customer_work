# 知识库版本原文预览

知识源与版本抽屉的“版本记录”增加“查看版本原文”。先浏览版本内文档目录，再按需打开正文；查看时展示不可变版本号、文档修订、来源版本和内容指纹。历史文档保持原始正文，不跟随当前修订指针变化。

## 调用与职责

- 调用方：KnowledgeSourceDrawer → KnowledgeVersionPreviewDrawer → knowledgeBase.ts。
- 入口：GET /api/aiconfig/knowledge-base/{knowledgeBaseId}/versions/{versionId}/documents，固定每页 20 条；GET .../documents/{revisionId}/preview。
- 下游：KnowledgeVersionPreviewService 读取 Admin 库既有的知识库、版本、成员、文档、修订和文档源。分页批量装载关联记录，查询次数不随当页文档数线性增加。
- 受影响场景：后台知识维护人员复核某个版本的依据。检索与预览共用 KnowledgeDocumentAccessPolicy，保持既有 PUBLIC/RESTRICTED 和各身份维度的匹配规则。
- 跨资源的版本归属和当前授权由 Service 编排；控制器只做参数、可信登录身份与功能权限入口。未引入新的文档存储或下载代理。

## 授权和失效语义

原文是新的数据出口，必须同时具备 knowledge-base:view 和 knowledge-base:source-preview。V105 只登记“预览知识原文”权限，不自动授予既有业务角色；管理员可在角色权限中明确授予。全局超级管理员仍沿用现有权限解析。

正文只在当前请求的租户内读取。指定知识库必须存在，版本必须属于该知识库，修订必须是该版本的成员，且来源、文档稳定身份和租户必须一致。查询参数中的 tenantId、subjectId 不参与登录主体确定。

历史修订与当前修订 ACL 必须同时允许当前 ADMIN_USER。文档被删除、源被停用或删除、修订/正文已清理时返回不可用；ACL 不允许时返回无权。目录中的不可读成员只返回版本、修订标识和状态，不包含标题、地址、指纹、正文或 ACL 主体清单。所有读取响应使用 Cache-Control: no-store。

新鲜度 SLA 超时不等同于文档撤回，本批没有以时间推测撤回。授权按本次只读事务中的状态核验；已被合法读取的内容无法从用户记忆或自行保存的副本中撤回。

## 页面行为

- 切换知识库、版本、登录主体或权限后，旧请求失效；正文立即清除。
- 每次重新核验先清除原文，失败不继续展示旧正文。目录和原文分别提供原地重试，无权、不可用和临时失败使用不同提示。
- 对返回的知识库、版本、修订和可读状态再做展示一致性核对，错误版本响应不呈现正文。
- 原文和来源位置按文字展示，文档中的 HTML 和 javascript 地址不会执行或触发站外请求。
- 桌面为目录与正文两栏；390px 在目录与阅读间切换，返回恢复到原文档按钮，长文滚动后返回操作保持可达。

## 后续范围

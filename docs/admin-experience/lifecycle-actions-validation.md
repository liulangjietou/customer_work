# 租户、任务与配置操作验收（G21）

本批承接 PR #228，属于 P1 第 8 项全站业务验收。已通过新专项、关联回归及六条真实数据库用例，最终完整门禁已通过；交付与远端 CI 状态以本分支关联 PR 为准。P2 性能尚未实测，H5 真机按用户要求暂缓。

## 调用链与职责

| 入口 | 下游 | 本次处理的业务边界 |
|---|---|---|
| 租户冻结、恢复、退租 | Tenant API → TenantService → 状态、访问版本及投递编排 | 确认期间身份变化、在途重复操作、失败保留状态 |
| 定时任务启停、触发、历史 | ScheduledTask API → ScheduledTaskService → 任务、历史记录和运行实例 | 行锁、失败恢复、历史目标、最近触发结果、实例释放 |
| 后台任务取消与详情 | AgentTask API → 任务运行时 | 确认身份、取消重试、详情切换和失败重试 |
| 项目会话详情与移出 | Project API → ProjectService → 会话关联与 WorkspaceSessionGuard | 只移出原关联，旧操作不能刷新后来打开的项目 |
| 配置回滚、灰度、审批、对比、审计 | ConfigVersion/Governance API → 版本及审批服务 | 表单目标、提交快照、审批与选项查询、身份和在途状态 |
| 用户角色及控制面选项 | CurrentView API → Role API → 用户表单 | 授权和目录属于同一身份，旧授权不得继续发起新身份请求 |

页面继续复用 `useQueryState` 与 `useRowMutation`。特有的弹窗目标和触发结果顺序留在页面，不增加新的通用框架或改动权限数据模型。

`ScheduledTaskService.callAgent` 每次通过 `AdminAgentInstanceFactory.build` 新建独占实例，因此该调用服务负责在成功、模型失败和超时后释放 Harness。使用 try-with-resources 保留异常语义，不修改工厂或共享实例管理。

## 失败证据与修复

- 原 21 条浏览器用例中，17 条复现确认身份、详情/历史迟到和错误恢复问题；另外 4 条原先未操作到可见控件，修正为可见 wrapper 后再执行。
- 扩展至 33 条后，14 条仍复现灰度锁、版本对比、审批与选项查询、项目移出和触发目标问题。
- 灰度“旧提交不能关闭新表单”曾因离场动画未结束而误通过。测试改为等待有限动画结束，实际失败后再修复表单代次。该错误的通过结果不作为验收证据。
- 角色授权与目录作为同一份查询结果接受；选项失败可重试，依赖选项的提交会阻止。重新登录后清理并重新加载当前身份选项。
- 灰度提交复制原租户选择和说明，在途锁定；关闭或重开表单后，旧结果不关闭当前表单。审批、对比和审计分别保留可恢复查询状态。
- 两条 Harness 成功/模型失败关闭用例先实际失败，再修复资源释放；追加超时后取消订阅、关闭实例和记录失败的正向用例。
- 真实数据库触发用例复现执行历史 INSERT 失败：当前 SQL 解析器将未引用的 `output` 列识别为语法关键字，租户插件在 JDBC 执行前解析失败。实体映射对该列添加标识符引用，保留租户插件和现有表结构；修复后成功、失败两种执行记录均能保存与查询。首轮另一个错误是租户测试夹具缺少必填密文列，补齐夹具后再验证，未当作产品缺陷。

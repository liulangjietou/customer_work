# 登录生命周期隔离与原主题保留

本批承接 #212，处理剩余清单第 3 项的登录权限、菜单初始化、退出调用方，以及第 4 项原配色恢复。订单后端仍在独立待办，不能用本批浏览器夹具证明真实订单授权。

## 调用链与职责

- Login.vue 应用完整登录结果 → auth store → 权限 API；每次登录、退出清理或服务端强制改密使原初始化失效。权限是 auth 的状态，成功响应也必须检查原登录是否仍有效。
- 路由守卫 → menu.bootstrap → 权限/菜单 API → 动态路由注册。menu 同时检查菜单刷新代次与登录代次，守卫只处理属于原登录的完成结果；旧失败不能清除新凭据或把用户带回旧目标。
- AppHeader 退出按钮 → auth.logout → HTTP 拦截器 → 本地 clear。退出按钮负责菜单、页签和导航收尾；网络失败也完成本地退出，旧按钮回调不能重置新账号页面。
- request.ts 负责全局错误提示与认证跳转，记录请求实际发出时的令牌和登录代次；代次仅为 Axios 内部元数据，不添加网络请求头。即使退出后复用了同一令牌，也不能让上一轮请求恢复副作用。
- 服务端返回 20002 时，auth 保留改密凭据、清空业务权限并持久化最小改密状态。守卫不把它当作普通初始化故障再次清除登录。
- 主题目录和 CSS 默认值恢复升级前的原配色，保留现有运行时主题生成、可访问前景色、跟随系统、自定义色及持久化机制。

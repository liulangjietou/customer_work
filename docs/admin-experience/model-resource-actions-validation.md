# 模型、资源与评测操作验收

本批承接后台 41 个静态入口的业务验收，修复模型治理、路由、实验、MCP、知识库、评测、SQL 数据源及渠道选项的已有操作。保留九套主题、自定义颜色和跟随系统；没有新增数据库迁移。

## 问题与职责

- ModelManage、治理/认证抽屉、路由和实验面板分别调用 model/modelExperiment API，经现有 Controller 和 Service 执行权限检查、凭据轮换、认证、版本及实验生命周期。旧组件在预检或确认后读取可变目标和输入，导致取消 A 后把 B 的草稿提交出去。弹窗代次、身份、输入锁和响应归属属于组件层；写入权限、业务预检及持久化继续由后端负责。
- MCP 管理、调试和契约弹窗经 MCP API 连接与采集。知识库独立探测/启停、SQL 数据源测试与渠道智能体选项同样具有独立异步生命周期，不能只依赖父页 CRUD 状态。复用现有 useCrudForm、useQueryState、useRowMutation 和 useAuthSubmissionScope；选项按实际 agent:view 权限读取，不把缺少选项权限显示为空列表成功。
- EvalCenter 经评测 Controller → EvalDatasetAdminService → EvalGateway 的 Store 创建工作集、导入、创建版本及审核。原服务用 save/upsert 新建，两个并发创建者能覆盖同一编号。创建改用 Store 的原子 create；明确的 EvalCaseConflictException 映射为重复资源，普通存储异常仍按原失败传播。编辑/导入保留既有 upsert 语义，Badcase 对 IllegalStateException 的兼容处理保持有效。

## 修复后的行为

1. 预检开始即锁定当前输入，确认、校验和写入使用本次目标及参数。关闭重开、切换对象、重新登录或权限改变后，旧回调不能写入、回填或刷新后续页面。
2. 查询失败显示可重试状态；多资源详情作为同一份快照更新。写入失败保留当前输入及原因，成功后才更新状态。实验显示后端 ACTIVATING/DEACTIVATING，不把任务受理直接显示为已生效。
3. MCP 调试保留只读查看与调用权限的区别；窄屏改为工具列表与参数上下排列。Ocean、Night 的模型表单及 Ember/Night 的评测表单保留原配色。
4. Ollama 按原页面约定允许留空凭据创建；其他提供商仍需凭据。凭据成功轮换或关闭抽屉后清理输入。
5. SQL 数据源探测按行锁定；渠道绑定选项不会跨身份保留，也不会在没有智能体查看权限时请求受限接口。

## 完整回归发现的权限夹具问题

首次完整 Admin 浏览器运行实际为 628 通过、2 失败。两条既有评测用例没有授予 `eval:view`，却要求读取运行记录和绘制数据图表；本批页面按后端原有权限契约阻止了查询。失败分别发生在最初基线记录出现前和绘图区数据像素检查，未把它们误报为评测类型污染或主题配色损坏。

仅为这两个正向用例补齐查看权限，原有数据隔离和实际图表像素断言保持不变；另加一条无查看权限不查询、授权后仅恢复当前类型、再次撤权清空数据的对照。三条专项均通过。新增浏览器用例合计 70 条（69 条操作专题与1条权限对照）。原始失败日志、报告及截图保留；完整 Admin631 与 H523 浏览器回归已通过。

此次修正仅涉及两个 E2E 文件，原有23份冻结文件均未改动。已通过的后端4,804条、两端单测和构建继续按原源码哈希保留结果，浏览器完整重跑结果另有本轮报告，未覆盖首轮失败证据。

## 验收边界

# 调用统计、命中看板与工具输入验收（G20）

本批承接 PR #227，属于 P1 后台全站业务验收。已完成范围验证与冻结后的七项完整本地门禁；其余专用动作、41 个入口的最终证据核对与 P2 性能实测仍需继续，H5 真机按用户要求暂缓。

## 调用链与职责

- `AgentCallStats.vue` → 调用统计分页、汇总、趋势、详情、回放、删除 API → `AgentCallStatsService` → Admin 存储或客服库只读门面。来源必须绑定生成当前列表的查询，不能从用户尚未提交的筛选框重新取值。
- `SensitiveHitLogBoard.vue` → 命中分页与统计 API → `SensitiveWordHitLogService` → 客服库门面。列表与图表必须使用同一次已提交筛选并整体接受结果。
- 工具箱容器 → JWT/AES 的密钥及编码组合输入。窄屏时编码选择框占满一行，容器负责统一换行布局，保留原主题变量。

页面复用 `useQueryState` 处理查询快照、失败重试和身份失效，删除复用 `useRowMutation` 管理确认和在途状态。后端业务规则和存储实现未改动；通过真实独立双库验证现有来源路由及精确租户边界。

## 为什么原测试没有发现

已有图表测试检查绘制与主题同步，没有覆盖失败响应、并行请求部分失败、分页时未提交的条件，以及同编号跨来源记录的操作归属。工具箱此前的“不溢出”检查也不能证明密钥输入具有可用宽度。

新增 22 条浏览器用例在产品修改前全部失败，实际复现了旧详情/回放覆盖新目标、旧 MOCK 结果残留、删除确认期间重登仍发请求、未提交来源影响旧列表操作、初次故障无恢复入口、越权读取智能体选项、分页带入未提交条件、汇总失败留下部分数据，以及 Ocean/Night 下 JWT/AES 输入被挤为零宽的问题。

## 已实现的行为

1. 列表、指标和趋势整体接受；首次失败显示可重试状态，后续失败保留上一份完整结果。分页沿用已提交筛选。
2. 详情和回放抽屉固定来源与记录，关闭、换目标或重登后作废旧请求；失败保留重试入口。MOCK 执行单独管理在途状态与错误。
3. 删除绑定原记录和来源，确认期间身份变化不再提交；同一记录在途锁定，完成后刷新原查询。
4. 统计只读用户不再请求智能体管理目录；仍可输入智能体编码筛选。权限变化会清除旧数据。
5. JWT/AES 在 390px 下将编码选择框换行，密钥输入实际宽度不少于 240px，并验证可聚焦、可输入。没有改动主题色、预设和明暗模式。

# 运营写操作与计费目标验收（G18）

本批继承 PR #225（53621f68），工作分支 `vibeCodingO/admin-operations-state`，仍属于 P1 第 8 项。H5 真机验收按用户要求暂缓，性能基线未开始测量。

## 调用链与原测试缺口

- 死信、语义缓存页面经 `api/ops`、对应 Controller 调用 `OpsAdminService`，再由跨库门面进入客服端 Store。死信重开只恢复待重投状态，实际投递由巡检器负责。
- SLO 页面经 `api/slo` 调用策略、评估、告警服务；保存是 upsert，新建不得携带先前编辑的 id；确认只改变告警确认状态，不能表示已经恢复。
- 计费页面经 `api/billing` 调用配额、价格、账单和告警服务。配额与单价是控制面写能力，普通租户可读自己的账单。导出需绑定当前结果对应的已提交筛选。
- `MybatisTenantQuotaStore` 为后台配额与运行时额度判定共用，显式跨租户访问必须自行保证精确租户条件，不能依赖已绕过的租户插件。

既有 G16 浏览器用例验证主查询和身份清理，未经过等待中的写确认、旧保存回调和随后打开的新表单。服务算法与 mock 用例不会暴露这些页面状态交错，也不会模拟真实数据库排序规则。

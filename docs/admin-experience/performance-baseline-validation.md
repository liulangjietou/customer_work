# 客服台分页与性能验收

对应已批准清单第 9 项：10,000 条工单、每页 20 条，以及 200 条会话消息的查询、切换和滚动测量。分页及关联功能回归、测量器自检和两轮正式性能测量已通过，冻结预算已独立复验；最终完整 Admin 632 条回归及五张最终截图核对已通过；Ready PR 与远端 CI 以本分支关联 PR 的当前状态为准。H5 真机验收继续按用户要求暂缓。

## 调用方、下游与改动范围

`UserTicketManage` 的分页操作调用 `pageTickets`，经 Admin `UserTicketController → UserTicketService → CustomerWorkTicketClient` 访问客服端 `AgentTicketController → TicketService → MybatisTicketStore`。页大小属于工单队列查询，20 条选择入口及页码重置放在页面层；后端保留已有参数及租户处理。

页面新增 10／20／50 条选项，切换大小回到首页，并保留当前会话与回复草稿。分页控件在窄屏允许换行。功能测试覆盖桌面从第二页切到 20 条、只发一次新查询，以及 390px 的 50／10 条切换和草稿保留；分页与已有客服台共 19 条浏览器回归、341 条单测及生产构建均已通过。最终完整回归的截图已等待下拉框关闭动画结束，分页选项与窄屏操作区均已核对。

## 本次复现的首屏阻塞

初轮为 18 条通过、分页用例在首屏等待失败。原样重跑仍失败；行数对照中 2 行分别配总数 2／10,000 均通过，10 行配总数 10／10,000 均失败。CPU 采样把约 10.6 秒定位到 Vue 更新过程中的参数校验警告与 Vite 控制台参数序列化，十行工单共出现 100 条无效参数警告。

根因是 `STATUS_TAG_TYPE.PROCESSING` 仍使用空字符串，而当前 Element Plus Tag 只接受 `primary/success/info/warning/danger`。该映射被队列和会话标题共同使用，修正在类型映射层，保留 `primary` 的现有主题语义；分页控件同时改用现有 `size="small"` 属性。修复后的验证沿用原首屏超时与草稿断言。

既有用例主要使用两行工单，全局测试只拦截 console error，未拦截这种 warning。新增用例保留首屏时限、分页及草稿断言，并要求没有无效参数警告；修复后完整场景 3.4 秒通过，原有 18 条客服台用例也通过。原始失败、行数对照及 CPU 采样均保留。

消息按既有 `useTicketConversation` 每页 30 条读取，经两个服务的实际 HTTP 和 `ChatLogService → MybatisChatMessageStore` 查询，沿“加载更早消息”分七页到达 200 条；测量不会忽略请求的 limit。

## 测量器的真实范围

`scripts/performance` 提供共享隔离数据集、实际 MVC/WebFlux HTTP 装配、浏览器采样和 SQL 基线工具。后端依赖从实际 Surefire 报告提取，测量前核对编译工作树的源码与当前分支一致，并保存编译产物指纹。

生产构建页面的工单列表、详情及历史消息使用真实 HTTP、生产 Controller/Service 和 MyBatis；生产工厂的租户、分页插件以及完整客服 Flyway 迁移保持原装配。登录身份、菜单、WS 就绪和辅助摘要为明确登记的夹具，不据此证明认证、WS 投递、模型推理或辅助服务性能。辅助面板的原始依据取自真实历史消息。

正式采样会记录设备、浏览器、源码与产物指纹、视口、主题、原始请求、页面呈现时间、逐帧间隔、长任务与截图。SQL 查询另保留 count、分页及对象映射耗时。每个场景先预热 10 次，再采集 50 次；P95 按升序第 `ceil(0.95*N)` 条计算。首次实测完成后再冻结预算，不预写达标结论。

## 已完成的 HTTP 自检

独立随机库使用本租户 10,000 条工单、另一租户 500 条对照和两个各 200 条消息的会话。实际 16 次 HTTP 检查通过：缺少测量令牌、写请求和非本次工单路径均被拒绝；首、次、末页各 20 条及总数正确；坐席筛选总数为 1,000；详情对应所选工单；历史七页为 `30/30/30/30/30/30/20`，共 200 条唯一消息；第二会话不会混入第一会话。

自检先复现并修正了两个测量器问题：独立创建工厂没有执行 Spring MapperScan，需要显式补齐注解 Mapper；客户端未声明 Accept 时 MVC 可能返回 XML，需要与正式前端 Axios 一样明确接受 JSON。未为此修改业务 Controller 或放宽产品权限。

三个自检尝试均已关闭并删除各自创建的随机数据库，未操作业务库。最终 HTTP 自检退出码为 0；这些数据用于证明测量器的调用链和清理流程，未将自检耗时作为性能样本。

## 正式测量与冻结预算

2026-09-16，在 MacBookPro18,2、10 核、64 GiB、macOS 26.6、Chrome 153.0.8010.37、JDK 17.0.16 上执行。两个视口为 1680×1050 与 390×844，固定 Ocean 主题；没有并行运行本任务的构建、Maven 或其他浏览器回归。保留机器当时的负载记录，不将本机结果外推为生产容量或外部模型时延。

每轮每场景预热 10 次、采样 50 次，合计 400 个浏览器样本与 250 个查询样本。首轮与独立复测使用相同生产构建和后端编译产物，各自创建、验证和清理随机数据库。两轮均无失败样本。完整分组值、条件、哈希与预算检查见 [测量证据](performance-baseline-evidence.json)。

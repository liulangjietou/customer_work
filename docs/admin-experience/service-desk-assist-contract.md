# 工单范围的摘要与建议草稿

基线：a1031def（PR #203）。本批接通 DESK-01 的 Admin 辅助入口、原文依据查看和建议采用。

## 调用、权限与归属

| 调用方 | 下游 | 业务影响 |
|---|---|---|
| TicketChatPanel / TicketAssistPanel | GET /api/ticket/{id}/assist → UserTicketController → UserTicketService → CustomerWorkTicketClient | 与当前工单一起读取辅助，不发送消息 |
| Admin 服务端短期坐席令牌 | AgentAuthWebFilter → AgentTicketAssistController → TicketService.find | 根据当前租户的真实工单推导会话，浏览器不能指定另一个 sessionId |
| 工单会话 | ConversationSummaryService.readCurrent → ChatMessageStore | 复用相同内容版本的已有摘要，否则整理当前原文及规则建议 |
| 采用动作 | useTicketReplies.setDraft | 只写当前身份和工单的内存草稿，继续使用既有发送、保存回执及对账流程 |

Admin 读取要求 user-ticket:view，查看依据沿用相同权限。App 接口沿用受保护的 agent 路径，拒绝无令牌和仅订阅令牌；跨线程显式传递由认证链写入的租户。会话 ID 由服务端工单确定，调用端只提供工单号。采用仍需本人负责、允许回复的工单状态和 user-ticket:reply。

没有新增数据库迁移，也没有改变令牌协议。客服库仍为 V26、Admin V104；后续分配版本前重新核对。

## 摘要和依据的语义

- 每次读取都核对当前历史内容版本。已有同版本模型摘要标记“已有 AI 摘要”，否则标记“规则整理”。不把规则建议冒充模型输出或知识库引用。
- 该 GET 不产生新的模型请求，也不打开默认关闭的自动摘要预生成开关。已有摘要的生成时间和实际来源随记录返回；历史查询失败返回错误。
- 依据显示实际使用的最近窗口、消息发送方、时间和摘录。较长记录标记截断；消息只能证明对话中出现过相关表述，不能证明退款等业务结果已核实。
- 下一步、情绪和已提到的处理均提示坐席核对。此处没有执行工具、查证订单或发布知识。

## 交互和并发

- 宽屏将摘要与工单操作放在会话旁；窄屏通过“工单信息”打开抽屉。原始依据可单独展开核对，返回后保持当前会话。
- 请求绑定工单、登录态、读取权限和消息快照。切单、权限变化、卸载使旧响应失效，刷新失败保留上次内容并停止采用。
- 收到新消息后显示更新提示，使用者刷新辅助后才能采用。请求发起于工单及历史加载状态稳定之后，避免切单时误用上一工单的消息版本。
- 空草稿直接采用；已有草稿先确认追加，完整保留原文。重复采用相同末尾建议不重复插入。
- 确认期间工单、身份、回复权限、消息版本或草稿版本变化则终止采用。保存结果待确认的同内容草稿不能被建议替换。
- 合并后遵守原回复 65535 字节上限，超长时保留草稿并提示。采用成功回到当前输入框，不调用发送接口。

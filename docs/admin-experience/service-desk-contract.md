# 坐席工作台与回复受理契约

本批接续客户消息回执，覆盖 Admin 工单队列、会话、工单操作、坐席回复和实时恢复。交接摘要与建议草稿另行实现，不能把本批基础工作台视为 DESK-01 全部完成。

## 调用链与职责

- 浏览器 `UserTicketManage` 展示队列；`TicketChatPanel` 展示会话；`TicketContextPanel` 发起工单操作。
- `ticketReplies` 按登录身份、租户、坐席和工单保存内存草稿及待核对回复；`useTicketConversation` 负责工单快照、历史分页与实时订阅。
- 回复经过 Admin `UserTicketController → UserTicketService → CustomerWorkTicketClient`，保留 `user-ticket:reply` 权限。Admin 服务端签发的坐席命令凭证只在服务间使用。
- App `AgentTicketController → AgentMessageAcceptanceService` 与可信 WS 命令入口共用受理逻辑。应用服务负责事务、幂等和通知编排；`Ticket.requireAgentReply` 判断工单自身状态与受理归属；存储实现负责行锁和消息唯一键。
- `TicketService` 的状态变更、用户活跃时间更新与回复事务读取同一工单行锁。客户消息在事务内取得当前工单快照后决定接收坐席，避免旧查询结果覆盖转派或把消息发给转派前的坐席。

## 回复协议

Admin 路径以 `/api/ticket` 为前缀；App 路径以 `/api/customer/agent/tickets` 为前缀。

| 操作 | 请求 | 返回 |
|---|---|---|
| 回复 | `POST /{ticketId}/reply`，`content`、`clientMsgId` | 实际保存的消息记录，Admin 使用现有 Result 包装 |
| 核对 | `GET /{ticketId}/receipts/{clientMsgId}` | `clientMsgId` 与 `message`；查询成功但无记录时 message 为 null |
| 恢复历史 | `GET /{ticketId}/messages?beforeId=…&limit=30` | 已保存消息；以实际数据库 id 分页 |

1. 浏览器为一次发送生成稳定标识；重试保持原标识和原文。内容按 UTF-8 校验，不超过消息表 TEXT 的 65535 字节；客户端标识最多 128 字符。
2. 消息唯一标识包含租户、工单、AGENT 类型、坐席和客户端标识。相同标识及内容返回原记录；更换内容返回冲突，不能覆盖已保存回复。
3. 新回复仅允许当前受理坐席在 PROCESSING 或 ON_HOLD 状态发送。已转派、关闭或解决后，原坐席仍可核对本人此前保存的消息；这不会重新打开工单或再次通知客户。
4. 工单锁、消息写入使用同库事务。事务失败后在事务之外查询唯一键胜者；查不到或查询失败均保持结果未知，不能误译为确定未受理。
5. 新消息提交后尽力推送客户。通知失败不撤销已保存回执；客户从消息表恢复。界面“已保存”只表示存储确认，不表示客户已收到、已读或业务已办结。
6. 旧客户端缺少 clientMsgId 的请求仍可发送，但不获得稳定标识去重和回执查询保证。正式部署使用 MySQL；内存实现不提供跨进程持久性及数据库事务保证。

## 前端恢复与身份边界

- 切换工单保留各自草稿和当前页面内的阅读位置。迟到响应只更新原工单；回复期间新编辑的文字不会被旧回执清空。
- 草稿仅保存在当前登录的内存中，退出登录、切换主体或租户会清理。刷新或关闭整个浏览器页面不会恢复未确认的本地草稿，不能承诺持久草稿。
- 网络请求写出后展示等待确认；明确拒绝与结果未知分开。未知记录必须先查询；只有查询成功且缺失、用户明确选择重试时才再次提交相同内容及标识。查询失败不自动重发。
- 首次打开、重新进入工单和 WS 重连后同步详情、历史和待核对回复。断线缺口超过一页时继续按游标补拉，直到覆盖已知记录；按实际 messageId 合并重复帧。
- 读取旧消息时不因新消息自动滚到底部。更早历史加载和切单恢复保持阅读位置；输入法组合阶段的回车不会发送，Shift+Enter 保留换行。
- 工单详情失败或未确认时暂停回复；只读权限、非本人受理和终态有明确说明。关闭工单后的原草稿仍可查看和复制。
- 工单操作依据领域状态显示。挂起工单可恢复处理或转回接单池，直接转给指定坐席需先恢复处理。挂起接口尚不保存原因，因此界面使用操作确认，不收集会被丢弃的输入。
- 状态进度只突出当前状态，不推断未发生的中间步骤已经完成。确认框绑定发起时的工单，切单或卸载后不能把确认结果应用到另一工单。

## 实时凭证与升级顺序

浏览器新领到的凭证为 `agent:tenant:expires:SUBSCRIBE:signature`。用途、租户和有效期都受 HMAC 签名保护。它只能订阅实时事件和发送心跳，不能调用 App 坐席 HTTP 接口，也不能通过 WS 发送客户回复。WS 到期主动断开，前端提前更新凭证，并在重连后补拉记录。

先部署支持新凭证和回执接口的 App 服务，再配套发布 Admin 服务与前端。旧浏览器的 WS 发送方式与新订阅凭证不兼容，Admin 前后端需一同升级并让用户刷新页面。

此前已签发的三段或四段命令凭证仍按原有效期校验。本批没有新增令牌撤销系统，不能宣称发布后立即撤销全部旧凭证；若部署需要立即失效旧凭证，需协调所有签发端与校验端轮换共享密钥并重连。

## 未纳入本批的能力

交接摘要、建议采用到草稿、知识来源授权预览、工作区输入受理和完整持久终态对账仍按总计划继续。没有新增模型生成内容、引用材料或真实业务结果的占位成功状态。

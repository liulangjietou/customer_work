# 设置与工具查询状态验收（G17）

本批继承 PR #224（7650183a），分支 `vibeCodingO/admin-settings-state`。P1 第 8 项全站逐页业务验收仍在进行；H5 真机已由用户明确暂缓，不计入本期完成条件。

## 修复范围与职责

- 菜单、字典、登录图片、主体配额的查询失败有可重试状态，更新失败保留已有结果。同令牌重新登录与权限变更清理旧身份数据。
- `useCrudForm` 从已有 `useCrudPage` 提取弹窗生命周期，共用于分页表单、菜单树、两级字典和字符串编码的配额等级。提交时锁定输入；失败保留表单；旧提交不能关闭新目标，旧图标上传不能回填新菜单。
- `useRowMutation` 支持字符串目标和确认框结束后的身份检查。轮播启停防重入，排序响应不会恢复旧身份列表；字典子项和用户档位可失败重试。
- 菜单已成功的写入保留待发布提示，即使用户已关闭原弹窗；发布失败可重试。窄屏树节点随内容增长，操作不被下一节点遮挡，只读用户不提供拖拽入口。
- SQL 控制台按数据源、库表与执行快照管理状态，失败保留上次结果，导出仍使用产生该结果的查询。HTTP 工具回车与按钮共用进行中锁，旧身份响应不回填。
- 主体配额等级与命中 Store 因业务需要显式跨租户，原普通文本比较会受数据库排序规则影响。现使用参数化精确租户条件，覆盖等级查询/更新定位/删除、命中明细和 XML 排行；Admin 原租户条件引用同一个公共定义。运营查询失败向上层传播；运行时快照失败的 Optional.empty 和观测写入容错保留。
- 保留九套主题、自定义主色与 System 随行。只读状态去掉空操作栏，配额配置说明可按需展开。

## 复现与专项验证

后端先在正式迁移的独立双库复现：等级/命中混入大小写不同租户、删除其他租户等级、保存挪用其他租户记录。最后一项在 RED 时查询原租户记录为空，报 EmptyResultDataAccessException，是实际数据被改归其他租户的证据。数据库查询故障被伪装成空等级/明细/排行也已先失败后修复。

修复后运营故障契约 5/5、真实数据库验收 14/14，零失败、零错误、零跳过。包括字典落库与消费 options、轮播公开列表的启停/排序/删除；对象存储删除只验证服务调用，不能当作真实 MinIO 删除证明。存量唯一索引不区分大小写，同编码插入可能被拒绝，但不会再挪用其他租户行。

前端当前有 28 条本批浏览器用例：四页查询/身份 8 条，三类表单 6 条，菜单/轮播/HTTP 动作 8 条，SQL/JSON 3 条，字典子项与配额用户 3 条。它们分轮运行，覆盖范围通过后开始完整回归。初次 25 条中 22 通过，三页缺少刷新入口，补齐后六条恢复专项通过。随后菜单全部操作权限的 390px 点击检查通过。

复现过程中修正了测试定位问题：数据库按钮带三角前缀、桌面菜单操作需先悬停，开关和已有值的选择框点击其可见控件而非被遮挡的内部 input。定位失败不作为产品缺陷统计。

## 最终门禁

全部本地最终门禁通过。Admin 341 条单测、405 条浏览器回归，H5 108 条单测、23 条浏览器回归及两端构建通过。本批 28 条浏览器用例均在此次完整回归内通过；六张最终 390px 截图逐张检查，归档后的 SHA256 与查看时一致。完整后端重跑 4,750 项，零失败、零错误、7 条外部条件跳过，报告 784 份。

首轮后端在 RedisSessionPersistenceTest 连接初始化时出现 Unexpected end of stream；失败日志与报告已归档。只读检查显示 Redis PING 正常、容器无重启和连接拒绝；相同配置的该单例及完整后端重跑均通过，没有跳过该测试，也没有修改或重启 Redis。源文件和测试冻结后顺序执行各门禁，23 个产品与测试文件在最终回归期间无变化，七道门禁均为终态退出码 0；PR 与远端 CI 在提交后另外登记。

## 验收边界

本批浏览器业务响应由受控 API 夹具提供，后端数据库操作另有真实迁移库证据；二者不能替代所有页面真实 HTTP 全流程验收。菜单拖拽/发布广播、轮播真实文件上传删除、字典全部写链路与配额运行时落档，以及其他看板写动作仍需对照全站矩阵补齐已有证明。

工具箱本批验证 JSON 和 HTTP，并修复原“只有 HTTP 调后端”的不准确注释；证书、JWT、Cron、Diff 和格式转换子工具仍需业务验收。全站第 8 项和性能第 9 项尚未完成；本批完成不能代表总目标完成。

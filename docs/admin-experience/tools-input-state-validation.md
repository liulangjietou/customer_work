# 工具输入归属与计算状态验收（G19）

承接 PR #226（2f40f369），分支 `vibeCodingO/admin-tools-state`。本批属于 P1 全站业务验收；其余页面专用动作、性能测量仍未完成，H5 真机按用户要求暂缓。

## 调用链与测试缺口

`DevToolboxView` 按路由挂载子工具；普通输入通过 `useToolStorage` 保存，AES、JWT 和证书临时密钥使用组件内状态。本地编解码、AES、正则和日期转换在浏览器运行；Diff、格式转换、Cron、JWT、证书经 `api/devtools` 调用后台与 starter 共用工具逻辑。顶栏 `TenantSwitcher` 经 `tenant/current-view` 确定当前权限及租户视角，再按控制面能力读取选项。

此前 SQL/HTTP/JSON 用例没有覆盖其他远程工具、输入的账号/租户归属和导出确认等待。算法测试也无法发现页面生命周期问题：旧的本地键只有工具字段名，清空只清显示值而未作废旧请求，重登后同一组件仍保留普通 ref，证书确认后又读取可能变化的文件与密码。

## 失败复现

产品未修改时运行35条浏览器用例：30条失败，4条本地计算正向通过；另1条证书清空用例使用精确文本误漏了带状态标记的真实条目按钮。修正为实际按钮定位后单独复跑，稳定失败，确认清空后旧上传仍显示条目。首轮与单例的日志、退出码、截图和 trace 分别归档。

失败事实包括：不同账号/租户读取相同输入、旧无归属键被自动读取、重登后临时秘密仍显示、清空/交换方向后旧结果回填、Cron先选响应覆盖后选结果、故障没有可重试状态、私钥导出确认期间重登仍发请求、迟到私钥重新打开显示窗口。四个本地正向用例使用真实浏览器计算，验证中文Base64与MD5、AES加解密、非法正则修正、UTC时间转换。

追加检查还复现了租户查询的中间步骤问题：旧控制面视角虽然未再显示，仍在重新登录后继续请求控制面选项；请求计数实际为1，预期为0。在两个请求之间核对身份和权限后，旧链路提前结束。另补充切换失败原地重试、旧切换成功不能重载新登录页面两条回归。

## 修复职责

- 工具容器先取得当前租户视角，再挂载工具。输入存储由账号和所属/有效租户共同分区；原无归属键原样保留，不自动迁给当前账号。缺少账号归属时只提供当前页面内的输入状态。
- 登录生命周期变化重建子组件，临时秘密随原组件清理；所有已选主题和工具计算方式保持不变。
- 远程计算复用 `useQueryState`。当前故障保留输入和已有结果，提供重试；清空、互换方向、换示例与组件卸载使旧请求失效。格式转换的输出标签采用产生结果的目标格式。
- 证书导出绑定产生当前条目的文件/密码及指定别名，确认结束后再核对身份和条目快照。清空和关闭立即撤掉显示及在途结果；不写本地持久化。
- 顶栏租户视角与选项作为同一次查询快照接受，身份改变清理旧选项；切换失败保留原视角，旧身份成功不触发当前页面重载。

## CI 捕获的命令收尾竞争

PR #227 首轮远端后端检查在 `SandboxCommandServiceTest` 中失败：事件流结束时尚未观察到工作区保存。调用链为 VibeCoding 执行接口 → `SandboxCommandService` → local/Docker 进程、工作区存储与审计。原测试在异步完成后立即验证调用，未控制收尾阶段，因此依赖线程调度。

新增受控同步用例稳定复现了提前发出终态、保存异常发生在流结束之后，以及执行线程丢失主体身份而保存到非原主体目录的问题。继续检查提前取消分支时，也复现了收尾前结束流。非零进程退出的正向用例用于确认原退出码契约保持不变。

修复由命令服务承担：入口捕获可信主体并随租户一起传入执行线程；保存调用返回前保持会话占用，随后释放状态，最后发送结果或错误及结束信号。取消、正常结束与异常走同一收尾位置。保持现有存储层的失败返回与日志策略，没有把命令退出码改造成对象存储持久化回执。

保存异常的审计也在收尾处只提交一次，避免先提交成功、随后用同一对象重复插入失败记录；该断言已实际失败并在修复后通过。

# 工作区消息检索参考

## 功能与边界

工作区每条助手答复现在可打开“本轮检索参考”，查看本轮自动检索实际提供的资料，并按保存的知识库版本读取原文。当前回答保留终态的消息 ID，历史回答保留服务端 ID；同轮 PROCESS 合并为最终答复后使用最后一条消息的 ID。

这批覆盖 Admin 工作区自动知识检索。它不把工具输出、模型文字中的标记或调用日志解析成可信来源，也不声称每条检索资料已被模型引用。工具返回的其他资料仍在执行记录中查看；H5 来源与业务结果继续单独接入。

## 调用链与职责

1. `ManagedKnowledgeSearchService` 从实际版本、成员和分片建立可信文档引用；外部检索节点不构造内部引用。`KnowledgeRetrievalService` 在排序与截断之后生成来源序号，保持正文中的编号一致。
2. `ChatService.chatStream` 为已鉴权的后台用户在本轮原生 RuntimeContext 绑定采集器；`KnowledgeInjectionMiddleware` 向已有采集器记录每个智能体本轮第一次自动检索结果。上下文之间不共享，采集器不保存问题或正文。
3. `ChatCompletionVerifier` 直接回读权威 AgentState，核对用户轮次、助手 ID、正文和结束原因后，才调用 `ChatKnowledgeSourcesService` 保存元数据。消息保存、来源保存、编码产物保存是三个独立结果，来源写入失败不篡改已保存答复的阶段。
4. 来源读取仍由工作区控制器校验当前登录用户的 `workspace` 权限和会话归属。服务根据当前身份重建 AgentMemoryScope，按租户、主体分区、智能体、会话和消息精确查找；存在来源记录时，再查权威消息是否仍属于原轮次。
5. 原文只通过本消息保存的来源序号读取。既有 `KnowledgeVersionPreviewService` 核对版本成员、文档是否可用以及历史和当前修订的 ACL。前端不提供知识库、修订或外部 URL 作为授权依据。

来源留存归属 Admin 聊天服务，因为它依赖工作区权限、消息状态和后台知识库；通用的检索元数据和本轮采集器位于 starter。没有新建公共存储抽象或更改其他宿主默认行为。项目没有现成 JsonUtil，JSON 沿用项目既有 ObjectMapper。

## 接口与状态

两个 GET 均以 `/api/workspace/{agentCode}/chat/sessions/{sessionId}/messages/{messageId}/sources` 为前缀，响应 `Cache-Control: no-store`：

| 路径 | 返回内容 |
|---|---|
| 前缀本身 | `RECORDED` 或 `NOT_RECORDED`，以及逐智能体检索结果与授权元数据 |
| `/{sourceId}/preview` | 此来源对应的 `KnowledgeDocumentPreviewVO`，原文保持历史修订 |

- `NOT_RECORDED` 表示没有查到来源记录，不能解释为未命中。
- `RECORDED` 下的 HIT、MISS、SKIPPED、DEGRADED 保留实际结果；空列表只表示没有自动检索记录，不推断其他工具是否执行过检索。
- 来源状态包括 AVAILABLE、FORBIDDEN、UNAVAILABLE、EXTERNAL。撤权或失效时隐藏之前的标题、知识库名、文档 ID、分片、分数和文档元信息。外部来源仅提供线索，不能借用内部预览接口或发起外部抓取。
- 读取故障保持错误状态并允许原地重试；不会返回伪造的空检索成功。
- 终态新增可选 `knowledgeSourcesSaved`。未参与采集的旧调用不输出此字段；仅收到 done、EOF 或流式正文不能推出保存成功。GET 重新确认记录后可更新本消息的保存提示，执行阶段不变。

## 持久化与隔离

新增 Admin V106 及手工镜像 `106-V106__chat_knowledge_evidence.sql`。分配前已检查全部活动 worktree 和共享库，最大版本均不超过 V105。没有修改既有迁移或共享库的迁移历史。

`ai_chat_knowledge_evidence` 只保存消息关联和检索元数据。唯一键包含 tenant、stateUser、session、message；重复保存不覆盖原记录，回读后还要核对精确关联、turnId 和完整快照。库表统一使用 utf8mb4_unicode_ci，但 Java 仍精确比较资源标识，防止大小写别名被当成同一条消息。分数统一去除无意义的末尾零，避免 MySQL JSON 将 0.750 读回 0.75 后误报保存失败。

新表的个人访问边界由既有会话归属与显式主体分区条件共同约束，不另建归属规则。即使残留来源元数据存在，权威消息已移除也不能恢复预览权限。

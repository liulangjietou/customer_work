### Q1 BPE 分词是怎么工作的？分词方式对应用有什么影响？

**考察点**：分词原理与成本。

**参考回答**

- **原理**：从最小单位（字符或字节）开始，统计语料中相邻单位出现的频率，反复把最常见的一对合并成新的词元，直到词表达到目标大小。
  字节级的 BPE 可以表示任意文本，不会出现“未知词”。
- **对应用的影响**：
  1. **成本**：同一段中文在不同模型中的 token 数可能差别很大，直接影响费用和上下文容量；
  2. **数字和代码**：数字可能被切成不规则的片段，这是模型做算术容易出错的原因之一；
  3. **计数和截断**：不能按字符数估算 token，要用模型对应的分词器计算。

**追问**：*为什么模型数不清一个单词里有几个字母？* 模型看到的是词元而不是字母，一个单词可能只是一个词元。

**减分回答**：“一个字就是一个 token”。

### Q2 Transformer 为什么需要位置编码？RoPE 是什么？

**考察点**：位置信息的表示。

**参考回答**

- **原因**：自注意力本身不区分顺序，打乱输入顺序，结果只是对应地打乱；需要额外的位置信息。
- **常见方式**：绝对位置编码（正弦函数或可学习的向量）；相对位置编码。
- **RoPE（旋转位置编码）**：按位置对 Query 和 Key 向量做旋转，使两者的点积只与它们的相对位置有关。
  这是目前主流大模型普遍采用的方式。
- **与长上下文的关系**：模型在训练时只见过一定长度的位置；通过位置插值等方法（例如 NTK 缩放、YaRN）可以扩展上下文长度，
  但扩展后的长距离效果需要验证。

**追问**：*模型声称支持很长的上下文，为什么长距离的信息利用效果仍然不好？* 训练数据中长距离依赖的样本较少；
注意力被大量内容稀释；位置扩展方法也有损失。所以关键信息要放在开头或结尾，并用评测来验证。

**减分回答**：不知道为什么需要位置编码。

### Q3 MHA、MQA、GQA 有什么区别？为什么现在的模型大多使用 GQA？

**考察点**：注意力变体与推理效率。

**参考回答**

- **MHA（多头注意力）**：每个注意力头都有自己的 Query、Key、Value。
- **MQA（多查询注意力）**：所有头共享同一组 Key 和 Value，KV Cache 最小，但效果可能下降。
- **GQA（分组查询注意力）**：把头分成若干组，每组共享一组 Key 和 Value，在效果和效率之间取得平衡。
- **为什么使用 GQA**：推理时 KV Cache 占用大量显存，限制了并发数和上下文长度；GQA 能显著减少 KV Cache，同时基本保持效果。

**追问**：*这对应用开发有什么意义？* 它解释了为什么不同模型在长上下文和高并发下的成本和速度差异很大；私有化部署估算显存时也要考虑这一点。

**减分回答**：只知道多头注意力。

### Q4 如何估算 KV Cache 的显存占用？

**考察点**：推理成本的量化。

**参考回答**

- **公式**（单个序列）：2（Key 和 Value）× 层数 × KV 头数 × 每个头的维度 × 序列长度 × 每个数值的字节数。
- **示例**：一个 32 层、32 个 KV 头、头维度 128、使用 16 位精度的 7B 模型，每个 token 约需要
  2 × 32 × 32 × 128 × 2 字节 ≈ 0.5MB；4096 个 token 的序列约 2GB。
- **启示**：并发数乘以上下文长度，才是 KV Cache 的总需求；长上下文和高并发时，KV Cache 可能比模型参数占用更多显存。
  GQA、KV Cache 量化、PagedAttention 都是为了缓解这个问题。

**追问**：*同样的模型，为什么输入越长，能支撑的并发数越少？* 每个请求占用的 KV Cache 与长度成正比，显存总量是固定的。

**减分回答**：只按模型参数量估算显存。

### Q5 FlashAttention 解决了什么问题？

**考察点**：推理和训练的效率优化。

**参考回答**

- **问题**：标准注意力需要在显存中生成完整的注意力矩阵（长度的平方），显存读写成为瓶颈，长序列时尤其严重。
- **做法**：按块计算注意力，在 GPU 的高速片上存储中完成计算，避免把完整的注意力矩阵写回显存；
  结果与标准注意力完全一致（不是近似计算）。
- **效果**：显存占用从与长度的平方相关降低到与长度线性相关，速度也明显提升，使长上下文的训练和推理更可行。

**追问**：*它会改变模型的输出吗？* 不会，它是精确计算，只优化了计算和存储的方式。

**减分回答**：认为 FlashAttention 是一种近似的注意力。

### Q6 MoE（混合专家）模型是什么？对部署和使用有什么影响？

**考察点**：模型架构的趋势。

**参考回答**

- **原理**：把前馈层拆成多个“专家”网络，每个 token 由一个路由器选出少数几个专家参与计算。
  总参数量很大，但每个 token 实际激活的参数量较小。
- **优点**：在计算量相近的情况下获得更强的能力；推理时每个 token 的计算量较小。
- **对部署的影响**：虽然计算量小，但全部专家的参数都要加载到显存中，显存需求按总参数量计算；
  多卡部署时专家之间的通信会带来额外开销。
- **训练中的问题**：需要负载均衡，避免少数专家过载、其他专家闲置。

**追问**：*一个总参数很大、激活参数较小的 MoE 模型，部署时需要按哪个参数量准备显存？* 按总参数量准备显存；按激活参数量估算计算量。

**减分回答**：认为 MoE 模型只需要激活参数对应的显存。

### Q7 大模型的训练一般分为哪几个阶段？

**考察点**：模型能力的来源。

**参考回答**

1. **预训练**：在海量文本上做“预测下一个 token”的训练，学到语言能力和世界知识。
2. **监督微调（SFT）**：用高质量的指令和回答样本训练，让模型学会遵循指令、按照对话格式回答。
3. **偏好对齐**：用人类偏好数据（RLHF、DPO 等）让模型的回答更有帮助、更安全。
4. **强化学习增强**（近年的趋势）：在数学、代码、工具使用等有可验证结果的任务上做强化学习，提升推理和 Agent 能力。

- **对应用的启示**：知识主要来自预训练，并有截止时间；遵循指令、调用工具的能力来自后训练阶段；
  应用层通过提示词、RAG 和工具来弥补知识的时效性和私有性。

**追问**：*为什么模型会“迎合”用户，即使用户说错了也表示认同？* 偏好对齐的训练可能让模型倾向于给出让人满意的回答。
在需要严谨判断的场景中，要在提示词中明确要求指出错误，并通过评测检查。

**减分回答**：“模型就是在大量数据上训练出来的”，说不出不同阶段的作用。

### Q8 什么是 Scaling Law？对应用开发有什么参考意义？

**考察点**：对模型发展规律的理解。

**参考回答**

- **含义**：模型的损失随参数量、训练数据量和计算量的增加，按幂律规律下降。
  相关研究（例如 Chinchilla）指出，在给定的计算预算下，参数量和训练数据量应该按一定比例同时增加。
- **近年的补充**：除了训练阶段的规模，推理阶段投入更多计算（例如更长的思考过程）也能提升效果。
- **对应用开发的意义**：
  1. 模型能力会持续提升，工程设计要能随之简化，而不是写死对模型缺陷的补偿；
  2. 小模型通过更多高质量数据的训练，也能在特定任务上达到不错的效果，支持“大小模型组合”的策略；
  3. 推理模型用更多的延迟和成本换取效果，要按任务选择。

**追问**：*模型越大越好吗？* 不一定。大模型的成本和延迟更高；对于简单任务，小模型足够且更经济。

**减分回答**：不了解这个概念。

### Q9 困惑度（Perplexity）和交叉熵是什么关系？

**考察点**：评估指标的基础。

**参考回答**

- **交叉熵**：模型对真实下一个 token 所预测概率的负对数的平均值，是语言模型训练的损失函数。
- **困惑度**：交叉熵的指数，可以理解为模型在每一步平均面对多少个“同样可能”的候选。值越低，说明模型对文本的预测越准确。
- **应用中的局限**：困惑度衡量的是语言建模能力，与完成具体任务的能力并不直接对应；Agent 效果还是要用任务评测来衡量。

**追问**：*应用开发中哪里会用到 token 的概率信息？* 例如用输出的概率（logprobs）估计分类结果的置信度，
或者检测模型是否“不确定”，但要注意不同模型的概率校准程度不同。

**减分回答**：认为困惑度可以直接衡量回答质量。

### Q10 采样参数的数学原理是什么？temperature 是怎么影响输出分布的？

**考察点**：采样机制。

**参考回答**

- **softmax**：模型输出每个候选 token 的分数（logits），经过 softmax 转换成概率：p_i = exp(z_i / T) / Σ exp(z_j / T)，其中 T 为 temperature。
- **temperature 的影响**：
  - T 小于 1：分布更集中，高概率的 token 更容易被选中；T 趋近于 0 时近似总是选择概率最高的 token（贪心解码）；
  - T 大于 1：分布更平坦，低概率的 token 被选中的机会增加，输出更多样，但也更容易出错。
- **top-k 和 top-p**：先截断候选集合（前 k 个，或者累计概率达到 p 的最小集合），再在集合内采样，避免选中极低概率的 token。
- **重复惩罚**：降低已经出现过的 token 的分数，减少重复。

**追问**：*工具调用和结构化输出场景为什么要用低 temperature？* 这类任务需要精确和稳定的输出，随机性越低，格式错误和参数错误越少。

**减分回答**：说不出 temperature 在公式中的位置。

### Q11 为什么大模型会出现幻觉？从原理上解释。

**考察点**：幻觉的根本原因。

**参考回答**

- **训练目标**：模型学的是生成“看起来合理”的文本，而不是“保证正确”的文本；在缺少知识时，也会生成流畅但错误的内容。
- **知识的局限**：训练数据有截止时间，覆盖不全，其中也有错误信息；模型无法区分自己“确实知道”和“只是觉得合理”。
- **解码过程**：逐个 token 生成，前面生成的错误会影响后面的内容，并可能被进一步“合理化”。
- **对齐的影响**：训练可能让模型倾向于给出回答，而不是承认不知道。
- **应用层的应对**：提供依据（RAG、工具）；允许并鼓励说不知道；对关键结论做校验；展示引用（见[通用第 01 期 Q4](../general/01-LLM基础.md)）。

**追问**：*模型对自己的回答很“自信”，能说明它是对的吗？* 不能。模型的语气和概率都不能可靠地反映答案是否正确，需要外部的验证。

**减分回答**：“模型还不够大”。

### Q12 Decoder-only 架构为什么成为主流？

**考察点**：模型架构的演进。

**参考回答**

- **架构类型**：
  - Encoder-only（例如 BERT）：擅长理解类任务，如分类、Embedding；
  - Encoder-Decoder（例如 T5）：擅长输入到输出的转换，如翻译；
  - Decoder-only（例如 GPT 系列）：统一用“预测下一个 token”完成所有任务。
- **成为主流的原因**：训练目标简单统一，容易扩大规模；生成能力强，通过提示词就能完成多种任务；
  推理时可以利用 KV Cache 高效生成。
- **应用中的对应关系**：生成和对话使用 Decoder-only 模型；Embedding 和重排序常使用 Encoder 类的模型。

**追问**：*为什么 RAG 中的 Embedding 模型和生成模型通常不是同一个？* 两者的训练目标不同：Embedding 模型专门训练来表示语义相似度，
生成模型用于生成文本。

**减分回答**：不了解不同架构之间的区别。

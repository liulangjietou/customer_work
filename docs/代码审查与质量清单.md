# 代码审查与质量清单

> 配合自动化：`AgentAssemblyAlignmentTest`、`SharedConstantAlignmentTest`、`./scripts/pre-pr-grep.sh`、
> `./scripts/run-focused-tests.sh`、`./scripts/run-frontend-checks.sh`。

## A. 改能力前：七条同类链路

任意改动「用户可见答复 / 中间件 / 缓存 / 敏感词」时，先确认是否影响全部入口：

| # | 入口 | 典型类 |
|---|------|--------|
| 1 | 同步 HTTP | `CustomerServiceService#chat` |
| 2 | SSE 流式 | `CustomerServiceService#chatStream` |
| 3 | WebSocket | WS `/ws/user` handler |
| 4 | 多 Agent | `/consult`、`MultiAgentOrchestrator` |
| 5 | 后台工作台 | admin `ChatService` / `AgentRunner` |
| 6 | 渠道 | `customer-channel` 管道 |
| 7 | Harness | `HarnessAgentFactory` 路由 |

**门禁**：`customer-work-starter` → `AgentAssemblyAlignmentTest`。

## B. 并发与会话

| 检查项 | 说明 |
|--------|------|
| 会话串行 | Redis / 进程内 `SessionLock`；Redis 降级后关注 `agent.state.conflicts` 指标 |
| Reactor 锁 | 加锁与释放是否同链 `doFinally`；避免 `RLock` 跨线程 |
| 渠道串行 | `KeyedSerialExecutor` + `ChannelInboundMessage#serialKey` |
| 乐观并发 | `saveIfVersion` / `version` 列；装饰器须转发新 default 方法 |
| Harness 释放 | 测试里 `HarnessAgent#close()`（见 `HarnessAgentReleaseContractTest`） |

## C. 多租户与数据权限

| 检查项 | 说明 |
|--------|------|
| 新表 | 业务表带 `tenant_id`，勿随意加租户忽略表 |
| 异步 | 消费前恢复 `TenantContext`（MCP、知识库回调、Outbox） |
| admin 视角 | 权限用归属租户，数据用当前视角租户 |
| 跨库 | 仅 `CustomerWorkFacade`；禁止 admin 直链 cw Mapper |

## D. 流式与中间件

| 检查项 | 说明 |
|--------|------|
| 用户可见性 | 用户看 `TextBlockDelta`，不是单独的 `AgentResultEvent` |
| 改写消息 | 用 `Msg#withContent` / `ForwardedText`，勿 `Msg.builder()` 重建（丢结束原因/审批态） |
| 块生命周期 | 补给正文须在文本块**结束之前** |
| 子智能体 | 带 `source` 的事件；H5 过滤策略与 admin 卡片一致 |

## E. 安全（第一轮）

| 检查项 | 命令 / 位置 |
|--------|-------------|
| 治理装配 | `./scripts/pre-pr-grep.sh` |
| 提交密钥 | `./scripts/verify-no-committed-secrets.sh` |
| 新数据出口 | MCP 工具契约、权限码是否必要（`sys_permission`） |
| 生产 fail-closed | admin Redis / 租户缺失 / 配额耗尽路径 |
| IM 回调 | 微信签名校验、`WeChatReplayGuard` 防重放 |

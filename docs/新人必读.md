# 新人必读（Onboarding）

欢迎！这份文档让你在 **15 分钟内**把项目跑起来、看懂结构、知道改哪里。读完按需再去看
[README](../README.md) 与 [详细技术文档](详细技术文档.md)。

---

## 1. 这是什么（30 秒）

一个**生产级智能客服系统**，基于 **AgentScope Java 1.0.12**，默认对接**阿里云百炼（通义千问）**。
一句话理解全项目：

> **每个能力 = 一个配置开关 + 一个可替换实现。** 默认用内置实现（离线即可跑、测试全绿），
> 改一行配置或写一个 Bean，就能换成 Redis/MySQL/百炼/Nacos 等真实后端，**业务代码不用动**。

工程是**两个模块**：
- `customer-work-spring-boot-starter`：可复用能力库（模型/记忆/RAG/工具/会话/安全/可观测/Nacos…），**自动配置**。
- `customer-work-example`：可运行的客服示例（启动类 + HTTP 接口 + 业务资源）。

## 2. 环境准备（一次）

- JDK 17+（推荐 21）、Maven 3.8+
- 一个百炼 API Key（[控制台](https://bailian.console.aliyun.com/) 申请）
- 可选：Docker（一键起 Redis/MySQL/Nacos）

```bash
cp .env.example .env        # 按需填写；密钥只走环境变量，绝不提交仓库
```

## 3. 跑起来（3 分钟）

```bash
export DASHSCOPE_API_KEY=sk-你的密钥      # 必填，否则启动报错（这是有意的安全设计）
mvn -q -DskipTests package               # 多模块一起构建
java -jar customer-work-example/target/customer-work.jar
```
看到 `Started CustomerWorkApplication` 即成功。打开 **http://localhost:8080/swagger-ui.html** 在线试接口。

发一条消息：
```bash
curl -X POST http://localhost:8080/api/customer/chat \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"u1001","message":"你们支持七天无理由退货吗？"}'
```

> 想连真实 Redis/MySQL/Nacos？`docker compose up -d` 起依赖，再把 `application.yml` 里对应开关打开。

## 4. 跑测试（不需要 API Key）

```bash
mvn test
```
**任何环境都应全绿**：外部依赖（Redis/MySQL/Nacos/百炼）相关用例在服务不可用时会**自动跳过**。
这是项目的硬性约定——你的改动也要保证 `mvn test` 绿。

## 5. 一次请求发生了什么（建立心智模型）

```
HTTP 请求
  → 过滤器链 (RequestId → 鉴权 → 限流)
  → CustomerServiceController            ← 接入层（example 模块）
  → CustomerServiceService               ← 编排：取/恢复会话 Agent
  → CustomerServiceAgentFactory          ← 按会话装配 ReActAgent
  → ReActAgent 的 ReAct 循环：推理 → 调工具 → 观察 → 再推理 …
       工具委托给 *Backend（默认 Mock，可换你的实现）
       模型走 Model（可叠加 私有化兜底 + 重试）
  → 回复；会话状态异步持久化
```
想看更细的时序图/类图 → [详细技术文档 §5、§4](详细技术文档.md)。

## 6. 代码从哪读起（推荐顺序）

> 主要逻辑都在 **starter** 模块：`customer-work-spring-boot-starter/src/main/java/com/richard/fyoung/customerwork/`

1. `controller/CustomerServiceController`（在 example 模块）——看有哪些接口。
2. `service/CustomerServiceService`——会话怎么取、怎么调 Agent、怎么持久化。
3. `agent/CustomerServiceAgentFactory`——**最核心**：一个 Agent 是怎么被"组装"出来的（工具/记忆/RAG/Skill/Hook/模型）。
4. `tool/`（含 `backend/`）——工具壳 + 可替换后端接口（你最常改这里）。
5. `config/CustomerWorkProperties`——所有 `customer-work.*` 开关一览。
6. `config/ModelConfig` + `FallbackChatModel`/`ResilientChatModel`——模型层装饰器。

## 7. 最常见任务：把它改成你自己的业务（10 分钟）

业务工具不写死，走接口。**接入你自己的订单系统**只需一个类：

```java
@Component
public class MyOrderBackend implements OrderBackend {
    public Mono<String> queryOrder(String orderId) {
        // 用 WebClient 调你的订单微服务，返回给 LLM 的文本
    }
    public Mono<String> queryLogistics(String orderId) { /* ... */ }
}
```
启动时它会**自动覆盖**默认的 `MockOrderBackend`（默认实现标了 `@ConditionalOnMissingBean`）。
同理可替换 `AfterSalesBackend` / `KnowledgeBackend`。

其他常见定制点：
- **系统提示词**：改 `CustomerServiceAgentFactory.SYSTEM_PROMPT`，或用 Nacos 配置中心热更新（`customer-work.nacos`）。
- **知识库**：`customer-work.rag.provider` 切 `simple`(向量)/`bailian`/`dify`。
- **会话存储**：`customer-work.session.mode` 切 `redis`/`mysql`。
- **技能**：在 `customer-work-example/src/main/resources/skills/<名>/SKILL.md` 加 Markdown 技能。

> 想作为**库**用在你自己的工程里？只引入 `customer-work-spring-boot-starter` 依赖即可（见 README §9.1），
> 任意包名都能自动装配。**完整范例**直接看模块 `customer-work-downstream-sample`（包名 `com.acme.support`）。

## 8. 配置开关速查

所有开关在 `customer-work-example/src/main/resources/application.yml` 的 `customer-work.*`，
完整表见 [README §7](../README.md)。常用：

| 想做的事 | 改这个 |
|---|---|
| 换模型厂商 / 兜底 / 重试 | `model.provider` / `model.fallback.*` / `model.retry.*` |
| 会话持久化 | `session.mode = memory/json/redis/mysql` |
| 长期记忆后端 | `memory.provider = memory/bailian/mem0/reme` |
| RAG 知识库 | `rag.provider = memory/simple/bailian/dify` |
| 开启鉴权/限流 | `security.auth.*` / `security.rate-limit.*` |
| 提示词热更新 | `nacos.enabled=true` |

## 9. 常见坑（少走弯路）

- **启动报"未找到百炼 API Key"**：没设 `DASHSCOPE_API_KEY`。这是有意的——仓库零密钥。
- **响应式里别用 `.block()`**：业务链路全异步；只有持久化落盘在 `boundedElastic` 上。
- **`@ConditionalOnMissingBean` 只在 `@Bean` 方法上有效**，别放在 `@Component` 类上（项目踩过，见技术文档）。
- **改提示词/模型后要回归**：AI 输出不确定，单测只保工程正确，效果看 [docs/EVAL.md](EVAL.md)。
- **单模块单独 `spring-boot:run` 失败**：先 `mvn install` 让 starter 进本地仓库，或从根目录构建。

# 新人必读（Onboarding）

欢迎！这份文档让你在 **15 分钟内**把项目跑起来、看懂结构、知道改哪里。读完按需再去看
[README](../README.md) 与 [详细技术文档](详细技术文档.md)。

---

## 1. 这是什么（30 秒）

一个**生产级智能客服系统 + 后台管理系统**，基于 **AgentScope Java 2.0.0 GA**，默认对接**阿里云百炼（通义千问）**。
一句话理解全项目：

> **每个能力 = 一个配置开关 + 一个可替换实现。** 默认用内置实现（离线即可跑、测试全绿），
> 改一行配置或写一个 Bean，就能换成 Redis/MySQL/百炼/Nacos 等真实后端，**业务代码不用动**。

工程是 **7 个模块**（5 个 Maven + 2 个前端），各自独立可跑：

| 模块 | 端口 | 类型 | 说明 |
|---|---|---|---|
| `customer-work-starter` | — | Maven | 可复用能力库（模型/记忆/RAG/工具/会话/安全/工单/用户/聊天记录…），**自动配置** |
| `customer-work-app-server` | **8080** | Maven | 可运行客服应用（HTTP + WebSocket 接口 + 用户工单系统） |
| `customer-channel` | **8081** | Maven | 多渠道接入演示模块（官方五套前端能力接入：admin/chat-completions/AG-UI/Studio/Channel），非主链路必需 |
| `customer-admin-server` | **8082** | Maven | 后台管理系统后端（MyBatis-Plus + Sa-Token，独立库 `customer_admin`，含坐席工单工作台） |
| `customer-work-gateway` | **8888** | Maven | 统一入口网关（可选）：Spring Cloud Gateway + Nacos 服务发现，把 8080 / 8082 聚合到同一入口 |
| `customer-admin-web` | **5174** | 前端（Vue3+TS+Vite） | 后台管理前端（含坐席工单工作台页面），**非 Maven 模块** |
| `customer-work-app` | **5175** | 前端（Vue3+Vite+Vant4） | 终端用户端 H5（登录/聊天/我的工单），**非 Maven 模块** |

> **分支策略**：`main` = AgentScope 2.0.0 GA，**有分支保护、禁止直接 push，必须走 PR**。开发前先从 `main` 切新分支。
> `legacy-main-1.0.12` 标签保留升级前基于 `1.0.12` 的最后状态（历史存档）。

## 2. 环境准备（一次）

- JDK **17**（shell 默认可能是 1.8，构建时务必显式切 17：`export JAVA_HOME=$(/usr/libexec/java_home -v 17)`）
- Maven 3.9 推荐；Node.js 24 推荐（Vite 8 最低要求 `^20.19.0 || >=22.12.0`）
- 一个百炼 API Key（[控制台](https://bailian.console.aliyun.com/) 申请）
- 可选：Docker（一键起 Redis/MySQL/Nacos）

```bash
cp .env.example .env        # 仅 Compose 自动读取；本地 Maven / IDE 仍需 export，绝不提交仓库
```

## 3. 跑起来（3 分钟）

### 后端（customer-work-app-server，8080）

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)   # 关键：默认 java 可能是 1.8，必须显式切 17
export DASHSCOPE_API_KEY=sk-你的密钥               # 必填，否则启动报错（这是有意的安全设计）
docker compose up -d mysql                         # 默认配置使用 MySQL，先确保数据库健康
mvn -q -DskipTests package                         # 多模块一起构建
java -jar customer-work-app-server/target/customer-work.jar
```

> **构建坑（本机 Maven 有内网镜像 profile 时）**：跑测试用
> `mvn -gs scripts/settings-central-direct.xml -s scripts/settings-central-direct.xml clean test -Djacoco.skip=true`——
> `-gs` 与 `-s` **必须同传**同一 settings 文件，否则全局镜像 profile 仍生效会挂死在内网 Nexus 上（无报错、极难判断）。

看到 `Started CustomerWorkApplication` 即成功。打开 **http://localhost:8080/swagger-ui.html** 在线试接口。

发一条消息：
```bash
curl -X POST http://localhost:8080/api/customer/chat \
  -H "Content-Type: application/json" \
  -d '{"sessionId":"u1001","message":"你们支持七天无理由退货吗？"}'
```

### 前端（按需）

分别在两个终端执行：

```bash
cd customer-admin-web
npm ci
npm run dev     # 后台管理前端，端口 5174（代理 /api → 8082）
```

```bash
cd customer-work-app
npm ci
npm run dev     # 用户端 H5，端口 5175（代理 /api、/ws → 8080）
```

> 想连真实 Redis/MySQL/Nacos？`docker compose up -d` 起依赖，再把 `application.yml` 里对应开关打开。
> `customer-work-app-server` 默认 `session.mode=mysql`，启动会自动建齐工单/用户/聊天记录等表（库 `agent_scope_customer_work`）。

## 4. 跑测试（不需要 API Key）

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 17)
export CUSTOMER_WORK_TEST_DATABASE=agent_scope_customer_work_test  # 推荐：与个人业务库隔离
mvn test        # 或加 -gs/-s 见上文构建坑
```

**任何环境都应全绿**（准确用例数以当前 CI 输出和根目录 `AGENTS.md` 的最近实测基线为准）：
外部依赖（Redis/MySQL/Nacos/百炼）相关用例在服务不可用时会**自动跳过**。这是项目的硬性约定——你的改动也要保证 `mvn test` 绿。

## 5. 一次请求发生了什么（建立心智模型）

```
HTTP 请求
  → 过滤器链 (RequestId → 鉴权 → 限流)
  → CustomerServiceController            ← 接入层（app 模块）
  → CustomerServiceService               ← 编排：取/恢复会话 Agent
  → CustomerServiceAgentFactory          ← 按会话装配 ReActAgent
  → ReActAgent 的 ReAct 循环：推理 → 调工具 → 观察 → 再推理 …
       工具委托给 *Backend（默认 Mock，可换你的实现）
       模型走 Model（可叠加 私有化兜底 + 重试）
  → 回复；会话状态异步持久化
```

**用户工单系统链路**（一句话）：终端用户经 8080 注册登录（JWT）→ 开会话与 AI 对话 → 命中关键词或按 7 态状态机
转人工 → 坐席经 `customer-admin-server`(8082) 代理接单回复；消息全程走 WebSocket 双向推送并落库。详见
[功能与配置全量参考 §6.22](功能与配置全量参考.md) 与 [详细技术文档 §22](详细技术文档.md)。

想看更细的时序图/类图 → [详细技术文档 §5、§4、§22](详细技术文档.md)。

## 6. 代码从哪读起（推荐顺序）

> 主要逻辑都在 **starter** 模块：`customer-work-starter/src/main/java/com/richard/fyoung/customerwork/`

1. `CustomerServiceController`（在 app 模块）——看有哪些接口。
2. `service/CustomerServiceService`——会话怎么取、怎么调 Agent、怎么持久化。
3. `agent/CustomerServiceAgentFactory`——**最核心**：一个 Agent 是怎么被"组装"出来的（工具/记忆/RAG/Skill/Middleware/模型）。
4. `tool/`（含 `backend/`）——工具壳 + 可替换后端接口（你最常改这里）。
5. `ticket/` `user/` `chatlog/`——用户工单系统三新域（充血状态机 `Ticket` + Store SPI）。
6. `config/CustomerWorkProperties`——所有 `customer-work.*` 开关一览。

## 7. 改哪里速查（三种最常见的加能力套路）

**给 starter 加一个可复用能力**（模型/记忆/工具后端/Store 等）：
- 定义接口 + `InMemory` 默认实现（`@ConditionalOnMissingBean`）+ 可选 `Mybatis` 实现（贫血 DO `entity/` +
  `BaseMapper` `mapper/` + 复杂 SQL 写 `resources/customerwork/mapper/*.xml`），装配写在对应 `*Config`。
- 持久化扩展一律走 **Store SPI 模式**（已套用 8 次：Approval/SlotFilling/DialogStage/Handoff/Feedback/
  Ticket/UserAccount/ChatLog），别发明新模式。
- 配置项加到 `config/CustomerWorkProperties`，默认值向"离线可跑"倾斜。

**给 customer-work-app-server 加一个 HTTP/WS 接口**：
- REST 加 Controller（WebFlux，返回 `Mono`/`Flux`），鉴权按需复用 `*WebFilter`（用户 JWT / 坐席 `X-Agent-Token`）。
- WebSocket 帧走统一 `{type,data}` 协议（`ws/WsFrame`），分发逻辑进 `chat/ChatDispatchService`。
- 已知与无权操作的资源才返回 403；可枚举业务资源优先让“未知/非本人”统一返回 404；非法状态流转返回 409，
  配套单测（`WebTestClient` 驱动）。

**给 customer-admin 加一个后台菜单/页面**：
- 后端：`customer-admin-server` 加 Controller（Sa-Token `@SaCheckPermission` 权限点 + `@OperationLog` + `Result<T>` 包装），需要 starter 能力时在自己的 `@Configuration` 里显式 new（admin 排除了 starter 自动装配）。
- 迁移：新增 `db/migration/Vxx__*.sql` 登记菜单/权限（含中文务必 utf8mb4 方式执行，见 CLAUDE.local.md 字符集坑），同步副本到 `mysql/02-customer-admin/`（加两位序号前缀）。
- 前端：`customer-admin-web` 加页面 + 在 `router/component-map.ts` 注册组件映射，按钮用 `v-permission` 指令控显隐。

> 想作为**库**用在你自己的工程里？只引入 `customer-work-starter` 依赖即可（见 [功能与配置全量参考 §9.1](功能与配置全量参考.md)），
> 任意包名都能自动装配，无需 `@ComponentScan`。

## 8. 配置开关速查

所有开关在 `customer-work-app-server/src/main/resources/application.yml` 的 `customer-work.*`，完整表见 [功能与配置全量参考 §7](功能与配置全量参考.md)。常用：

| 想做的事 | 改这个 |
|---|---|
| 换模型厂商 / 兜底 / 重试 | `model.provider` / `model.fallback.*` / `model.retry.*` |
| 会话持久化 | `session.mode = memory/json/redis/mysql` |
| 长期记忆后端 | `memory.provider = memory/bailian/mem0/reme`（prod 启用长期记忆时门禁只允许 `memory`，且记忆/同意均强制 JDBC；外部 Provider 当前限非生产） |
| RAG 知识库 | `rag.provider = memory/simple/bailian/dify` |
| 开启鉴权/限流 | `security.auth.*` / `security.rate-limit.*` |
| 用户工单系统 | `ticket.store-mode` / `user-auth.*`（env `CW_USER_JWT_SECRET`）/ `chat-log.store-mode` / `agent-access.secret`（env `CW_AGENT_WS_SECRET`）/ `tool-backend.mode` |
| 提示词热更新 | `nacos.enabled=true` |

## 9. 常见坑（少走弯路）

- **shell 默认 java 是 1.8**：构建/测试前务必 `export JAVA_HOME=$(/usr/libexec/java_home -v 17)`。
- **本机 Maven 内网镜像 profile**：跑 mvn 时 `-gs` 与 `-s` 必须同传项目 settings（见 §3 构建坑）。
- **启动报"未找到百炼 API Key"**：没设 `DASHSCOPE_API_KEY`。这是有意的——仓库零密钥。
- **响应式里别用 `.block()`**：业务链路全异步；只有持久化落盘在 `boundedElastic` 上。
- **`@ConditionalOnMissingBean` 只在 `@Bean` 方法上有效**，别放在 `@Component` 类上（项目踩过，见技术文档）。
- **改提示词/模型后要回归**：AI 输出不确定，单测只保工程正确，效果看 `IntentEvalRunner` + 真实链路抽检（功能与配置全量参考 §6.11）。
- **依赖版本变更后必须 `clean`**：增量编译不检测 classpath 变化，会误报编译成功。
